## 从观测到可检验的机制解释

完整 turn 可按客户端时间轴恒等拆成“arrival 到 first token + first 到 last token + 完成处理尾部”。首 token 之前同时包含控制器工作、排队/调度、必要 KV 回载与 prefill；本次报告没有可直接识别这些阶段因果份额的共同状态重放。DMA 可异步重叠，不能把传输计数或不同 clock 的时长直接加到客户端关键路径。

**观察一：写策略差异主要出现在首 token 前。** Rebuild / WT 到 WB 的 turn 均值为 4.625 → 3.769 秒，TTFT 为 1.979 → 1.051 秒；输出均值 530.6 → 529.1 tokens，TTFT 之后的剩余均值略增。这排除了“这组总时延差仅因为答案显著变短”这一解释，但尚不能区分同步备份等待、调度状态、回载 / prefill 或运行顺序各占多少。

**观察二：少算 prefill 并不足以预测整体更快。** Redundancy40 / WB 比 Rebuild / WB 的 actual prefill 总量低 17.2%（114731 对 138594），但 host load 为 41856 对 10432，turn 均值反而为 4.339 对 3.769 秒；TTFT 为 1.558 对 1.051 秒，输出也更长（553.7 对 529.1 tokens）。这支持进一步检验“可复用前缀的位置、回载代价、调度等待和 decode 长度共同决定关键路径”的模型；这些不同轨迹本身不足以拟合或宣称一个新的代价定律。

**观察三：固定阈值的动作覆盖与资源压力需要分别检查。** Fixed4096 仅一次 APPEND，不能用其与 Rebuild 接近的均值证明一般的 APPEND/REBUILD 策略有效；本轮 host 尚未表现为容量瓶颈，也不能把 retirement ack 成功等同于释放受压资源。调整 4096 或 40% 只是新的实验参数，单凭阈值换一组数并不构成课题贡献。
