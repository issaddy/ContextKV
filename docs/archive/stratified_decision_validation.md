# 分层成对决策验证：90 对开发集诊断

> 归档记录：保留当时的设计、结果与复用依据；其中“下一步”和执行计划不代表当前任务。当前工作仅以[实现清单](../implementation_plan.md)为准。

核查日期：2026-10-24。**本批结果不支持成本计划器优于简单策略。** Lookup 的平均单步 regret 为 366.55 ms，高于固定重建的 129.14 ms 和 8192-token 阈值的 177.11 ms；positive 版本虽改善首 token 预测，却退化为全部追加，regret 增至 437.05 ms。以下如实保留这些负面结果，没有据此调参或拟合新模型。

原始数据及来源位于 `runs/remote-h200-expanded/decision-dev-stratified/` 的 `cases.jsonl`、`pairs-lookup.jsonl`、`pairs-positive.jsonl` 及相邻 manifest。独立统计保存在 [independent-analysis.json](../../runs/remote-h200-expanded/decision-dev-stratified/independent-analysis.json)，包含输入文件 hash、全部逐 pair 数值、case/session/cache-state/plan-reason 分组、重复稳定性和计算定义；该文件由 Git 忽略。测试集未参与分析。

## 1. 这组数据回答什么问题

从真实 Cloud P2 开发轨迹按会话与 epoch 年龄选取 15 个非初始轮次，来自 5 个会话。每个会话恰有 3 个 case，分别处于 `turns_since_rebuild=0/1/2`。每个 case 在 cold、gpu_ready、host_only 三种状态各重复两次，共 **90 pairs、180 次候选生成**。初始轮只有一个候选，原 manifest 单列排除。Positive 仅对这些相同输入和报价离线重新决策；已逐字段核对两份文件的实测回答、计时及其他 observation 完全相同，不能把它算作又一批硬件样本。

每臂独立重置并准备相同历史缓存，执行次序按固定种子打乱。采集器确认 quote 形态一致且 active/queued 为零，决策压力为 **concurrency=1**，不是原 Cloud c4 轨迹的并发重放。所有回答上限均为 1024，线上残差更新关闭，`prediction_control_ms=0`。

主计时为 `server_elapsed_ms`；定义 `Δ=T_APPEND−T_REBUILD`，正值表示该次 REBUILD 更快。报告中的 regret 为所选臂时间减去同一 pair 两臂时间的最小值。它没有质量调整，不能称“质量 oracle”。两臂共享同一冻结历史；固定策略并未生成各自后续历史，因此这些是**单步同条件对照，不是闭环基线收益**。计时也不包含 fixture、prepare、retire、ledger commit，不能替代完整用户响应时间。采集合同见 [decision_pairs.py](../../profiling/decision_pairs.py)。

独立单位最多是 5 个会话、15 个固定 case；三种状态及两次重复不构成 90 个独立任务。本报告只给描述统计，没有显著性检验。表内 P95 是这 90 条观测的经验分位数，不是部署尾延迟保证。

## 2. 与固定策略的同条件对照

8192 阈值严格沿用当前实现：冻结 APPEND 输入超过 8192 tokens 时选 REBUILD，否则选 APPEND。没有在这 90 对结果上寻找阈值。全部 pair 中实测较快臂为 REBUILD 50 次、APPEND 40 次。

| 选择规则 | APPEND / REBUILD 次数 | 平均 regret（ms） | 经验 P95 regret（ms） | 最大 regret（ms） |
|---|---:|---:|---:|---:|
| Lookup 成本计划 | 84 / 6 | 366.55 | 997.37 | 1843.18 |
| Positive 离线重评分 | 90 / 0 | 437.05 | 1833.55 | 2009.01 |
| 固定 APPEND | 90 / 0 | 437.05 | 1833.55 | 2009.01 |
| 固定 REBUILD | 0 / 90 | **129.14** | 484.73 | 490.20 |
| 固定阈值 8192 | 54 / 36 | 177.11 | 793.13 | 965.72 |

两估计器均有 82/90 pair 的两臂处于标定支持域；另外 8 对走原固定阈值回退，在本数据中均选 APPEND。支持域只说明测量范围可用，不保证预测准确。按绝对差 1 ms 作为平局容差，标定 pair 的预测符号正确数为 lookup **42/82**、positive **46/82**。

按缓存状态分解，每格包含 15 cases × 2 repeats：

| 缓存状态 | Lookup 支持 / 切换 | Lookup regret | Positive regret | 固定 REBUILD regret | 阈值 8192 regret |
|---|---:|---:|---:|---:|---:|
| cold | 30/30；6 次 | 285.92 | 497.42 | 94.73 | 225.21 |
| gpu_ready | 26/30；0 次 | 406.15 | 406.15 | 146.87 | 152.86 |
| host_only | 26/30；0 次 | 407.58 | 407.58 | 145.82 | 153.28 |

以上 regret 单位均为 ms。所有 6 次 lookup 的成本触发切换都发生在 cold，且这 6 对实测 REBUILD 均更快。Positive 取消了它们；新增 regret 合计 6345.03 ms，除以 90 即两方法均值差 **70.50 ms**。这解释了本批 positive 决策退化的全部来源。

## 4. 为什么首 token MAE 改善，决定却更差

相同 90 对真实观测上的阶段误差如下。差值 MAE 比较的是两候选的预测差与实测差，全部行都保留，包括未标定的诊断预测；只看 82 个标定 pair 的数值也保存在 JSON 中，结论相同。

| 误差指标 | Lookup | Positive |
|---|---:|---:|
| 180 臂首 token 点预测 MAE（ms） | 7.94 | 2.61 |
| 首 token 差值 MAE（ms） | 10.75 | 3.63 |
| Decode 差值 MAE（ms） | 557.42 | 557.42 |
| 完整服务时间差值 MAE（ms） | 560.02 | 558.39 |

**第一，改善了较小的误差项。** 本批实际首 token 差的平均绝对值为 50.76 ms，Decode 差为 562.20 ms。Positive 改善首 token 后，完整时间差 MAE 仅改善约 1.63 ms；两个模型仍使用同一个候选无关的输出长度先验。

利用实测 `D=(N−1)·TPOT`，可把 Decode 差精确分解为：

`ΔD = ΔN · mean(TPOT) + mean(N−1) · ΔTPOT`

长度分量的平均绝对值为 **550.09 ms**，TPOT 分量为 **26.80 ms**；84/90 对中前者更大。这只是代数分解，不是改变输出长度的因果实验。当前模型两臂预测长度相同，而实际 APPEND−REBUILD 输出长度均值为 +58.76 tokens，方向也并非始终为正。

例如 case `9d4e40d4` 的 gpu_ready 第 0 次重复：APPEND/REBUILD 输入 10168/5011、输出 903/517 tokens，两边均自然停止。APPEND 首 token 实际快 32.77 ms，却因 Decode 多花 1869.23 ms 而最终慢 1836.46 ms。模型两臂都预测 568 个输出 token，Decode 差仅预测 38.60 ms。Positive 已把首 token 差预测到 −30.14 ms，仍不能补上长度遗漏。反例 `2744b5f4` 输出为 317/360，较长 APPEND 输入反而产生较短答案；不能简单假设“重建一定更短”。

**第二，新的保守误差量直接改变了门槛。** 当前冻结参数是 `delta_abs=0, delta_rel=.05, z=1, min_stable_turns=2`。82 个标定 pair 的切换门槛均值，lookup 为 **112.67 ms**，positive 为 **952.06 ms**。Positive 每臂使用 472.57 ms 的 OOF P99，再把两臂误差保守相加；最大 OOF 误差来自并发 4 的 16K/8K 单元，却同样进入本次并发 1 的所有决策。这是当前无条件误差量的保守性，不是点预测变差。

不能为了本表降低 P99 或 `z`。下一步可以在独立开发数据中评估分并发/状态的**成对成本差误差**，明确两臂误差的相关性与样本量，继续保留样本不足时的回退；不要把训练残差或这 90 对上最合适的阈值当作置信界。

本批 `delta_abs=0`、预测 control 成本也为 0，因此退化**不是**把旧 Cloud `control_ms` P95≈436 ms 乘二造成的。另行发现的序列化热点可降低工程开销，但不能修复本表中的候选长度差或约 952 ms 的误差门槛；两条改进应分别验证。

## 5. 截断与重复稳定性

180 个臂中 **18 个截断**：APPEND 12 个、REBUILD 6 个；涉及 12 对，其中 6 对两臂同时触顶。主表未删除任何截断。仅为敏感性描述，在两臂均未截断的 78 对上，平均 regret 仍为 lookup **396.64 ms**、positive **472.95 ms**、固定重建 **149.01 ms**、8192 阈值 **204.36 ms**。因此负面排序并非仅由截断造成，但没有质量评分时，较短回答仍可能不充分，不能据此宣布固定重建是最终优胜方法。

case `c65e01ec` 两臂均输出 1024 且终止原因是 `length`；这不是自然输出长度相等的证据。它的 gpu_ready 第 0 次重复仍有 67.94 ms Decode 差，体现相同 token 数下的上下文长度/TPOT 效应，不能外推为完整答案收益。

45 个 case×cache-state 组中，两次重复的实测快慢方向 **45/45 一致**；两臂输出 token 数各自 **45/45 一致**，两估计器选择也均 **45/45 一致**。两次实际 `Δ` 的绝对变化均值为 2.05 ms，最大 7.06 ms。这说明这一次隔离采集内部稳定；只有两次重复，不能据此证明跨负载、跨时段或跨会话稳定性。

## 7. 最小下一步

1. **先完成同预算固定策略和回答质量对照。** 保持本次模型与参数冻结，运行已具备的 controller dev 矩阵，随后单列原生 B0/B1；统一 1024 输出上限和缓存初态。用真实 judge 与盲审判断较短 REBUILD 回答是否合格，不能把本次最快臂直接作为最终质量准入或 B6。
2. **再决定是否值得增加候选条件长度先验。** 主要残差已经定位到输出长度，不是继续改 first-token 插值就能消除。只能从独立 dev 会话的已完成生成建立简单先验，与共享先验公平比较；保留原始 90 对作为诊断记录，不能用它们拟合后再声称独立验证。特征仅取当前可见输入/历史，不得读取当轮真实答案长度。
3. **单独验证误差门槛与滞回。** 在独立分层成对数据上比较成本差误差的估计方式，再用完整闭环检验切换频率和收益；保留当前固定回退。先不要增加全局调度、新 attention kernel 或更多拟合器。

目前可以确认的是：同输入/同缓存形态的反事实采集与离线重评分管线可运行；更低的首 token MAE 没有自动转化为更好的动作。B 的性能贡献仍未成立，固定策略是必须超过的实际对照。
