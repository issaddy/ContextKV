# 当前评测结果

固定 Qwen3-32B BF16 与辅助权重，每个 benchmark 使用相同的 20 题、公开参考历史、并发 4。普通文档问答基线为“问题 → 检索 → 常规拼接 → SGLang Native → 回答”。

四项质量高于普通问答基线，三项完整 P95 更低；VersionQA 的 P95 仍高 6.44%。

前三项质量乘以 100；Loong 为作者百分制。P95 包含排队、检索、辅助编码、必要计算及回答。GPU/Host 为整批物理驻留内存的时间积分，包含辅助模型；它不是 GPU 利用率。

## 上下文与缓存协同

| Benchmark | 主模型输入 / 输出 token | 额外 READ | GPU 命中 / Host 回载 token | 实际 prefill token |
|---|---:|---:|---:|---:|
| MultiDoc2Dial | 8723 / 2756 | 0 | 960 / 0 | 7763 |
| MT-RAG | 34778 / 4633 | 0 | 1664 / 0 | 33114 |
| VersionQA | 37843 / 1744 | 0 | 2048 / 0 | 35795 |
| Loong | 115226 / 2463 | 0 | 448 / 64 | 114714 |

Loong 最新队列的缓存命中与回载共 **512 token**，占输入约 **0.44%**；性能改善主要来自消除重复读取、缩小主模型实际输入及辅助计算精简。当前不能把这部分提速计作 InfoFlow 的非前缀复用收益。

机制上，KV 驻留费用参与选材，GPU 容量参与总体上下文份额，最终选材顺序与缓存计价一致；引擎仍按真实驻留在 Native 与 InfoFlow 之间选择。本轮队列以冷启动和少重访为主，缓存的独立完整响应收益尚未由这组结果证明。

## 当前改进重点

- Loong：代表片段覆盖各来源，仍可能遗漏决定答案的条件或跨文档关系，需要增强需求与互补证据的对应。
- VersionQA：继续减少查询理解、检索与共享证据编码关键路径的耗时。
- KV 协同：当前冷队列重访较少，需在真实跨轮原文复用中衡量独立缓存收益。
