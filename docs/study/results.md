### 监督与建议核查

- 新增 64 个任务／来源状态，覆盖 32 个会话；来自 MultiDoc2Dial 官方训练对话，复用已有独立构造的关系／版本训练资料。评测题未用于拟合。
- 集合采集 48/16 个训练／开发状态、374 个实际答案标签；停止采集 24/8 个训练／开发会话、64 个终端答案。候选资产为 `models/shared-evidence-diverse`、`models/shared-stop-diverse.pt`。查询和字段权重保持固定。
- 修复字段标注超窗：按生成器真实 token 配方分包，保留来源地址并跨批关联连接字段；四个状态已通过实际标注。集合采集采用线上回答预算，停止扩展复用线上来源依赖闭包。

| 建议 | 核查结果与处理 |
|---|---|
| ReadyBatch 增加 50ms 超时 | 当前立即消费就绪输入，没有等批满；不增加等待。 |
| 快照缓存 5 秒、auto 先估值后打分 | 无计算时已经复用快照；auto 在打分前选择路径。保留现有机制。 |
| 按 GPU 命中率降低重算比例 | 命中率不决定跨块注意力误差；只修改报价还会使报价与执行的比例不同。不采用阈值规则。 |
| 固定追加最近三轮 | 历史已经是预算内完整消息，非逐 token 标签裁剪；不越过同一历史预算追加。 |
| 复述历史条件指令 | MT-RAG 提高、MultiDoc2Dial 回退，未替换原指令。 |
| 解码图改为 64 对齐 | 当前已有 `(length-1).bit_length()`；更细桶增加图实例，不能推出总显存节省 50%。保留分档，减少重复复制。 |
| 高频来源改小块、DQN、跨会话数据库 | 不新增。普通来源窗口上限是 2048 token，随题总体窗口是 256，物理页是 64。现有质量头和实时费用已共同参与选择，给定频次阈值与预期收益百分比尚无实测依据。 |

后续重点是辅助处理与扩展收益的成本校准、独立技术问答训练覆盖和回答相关性；InfoFlow 仍需降低稀疏注意力与解码费用。完整指标、各候选逐题结果位置和训练规模见 [hotpath.json](../../results/hotpath.json)。

## 连续真实会话：上下文与 KV 协同优化

固定 Qwen3-32B BF16 和辅助权重，每个 benchmark 为 4 个真实会话、各 5 个相邻问题，共 20 题，并发 4。方法使用自身已提交历史（P3），保留无重访的轮次；每个方法/数据集冷启动一次，会话内不清缓存。普通基线为检索、常规拼接、SGLang Native 和回答。

全部主队列交付并评分 20/20。质量乘以 100，完整 P95 包含排队、检索、辅助编码和回答；GPU/Host 为在线物理驻留内存的时间积分，评分费用另计。

| Benchmark | 方法 | 质量 | 完整 P95（秒） | GPU / Host GiB·s | 在用 KV 峰值 GiB |
|---|---|---:|---:|---:|---:|
| MultiDoc2Dial | 普通文档问答 | 16.83 | 8.34 | 2174.0 / 598.3 | — |
| MultiDoc2Dial | 改进前 ContextKV | 21.10 | 6.14 | 1767.0 / 525.2 | 3.219 |
| MultiDoc2Dial | 本轮 ContextKV | 25.91 | 7.43 | 1289.7 / 365.7 | 1.141 |
| MT-RAG | 普通文档问答 | 52.95 | 24.97 | 6367.6 / 1759.3 | — |
| MT-RAG | 改进前 ContextKV | 54.24 | 23.13 | 7262.2 / 2190.2 | 8.000 |
| MT-RAG | 本轮 ContextKV | 61.81 | 14.08 | 3307.6 / 966.5 | 3.672 |

相对改进前，MT-RAG 质量增加 **7.58 个百分点**，完整 P95 降低 **39.13%**，GPU 累计占用降低 **54.45%**。MultiDoc2Dial 质量增加 **4.82 个百分点**，GPU 累计占用降低 **27.01%**，P95 上升 **21.08%**。两项质量、P95 和 GPU 累计占用均优于普通文档问答基线；MultiDoc2Dial 的尾延迟回退仍需改进。

MT-RAG 的综合质量提高并非所有子项同时上涨：算法指标从 32.96 升到 40.65，忠实性从 75.29 升到 87.46，回答相关性从 85.50 降到 80.00。

### 根因与实现

| 根因 | 本轮实现 |
|---|---|
| 回答重复展开旧问题，生成费用又进入后续历史 | 最终回答明确当前问题范围，保留必要事实、条件、命令与引用；同一指令用于预算、执行和校准。MT-RAG 输出从 10784 降到 4360 token，输入从 66153 降到 42480。 |
| 保留单个来源被误当成可复用完整 Native 前缀 | 只有前置来源也被保留，才计入整条 Native 前缀的未来收益；线上和重放共用同一规则。 |
| 只改淘汰优先级，整段问题/回答尾部仍进入缓存 | checkpoint 只接纳稳定原文；近期需求前缀留在 GPU，其他稳定原文在 Host 副本就绪后由 HiCache demote 归还 GPU 页；私有尾部结束即释放。 |
| InfoFlow 逐请求执行，多个 query head 重复读取同组 KV | 合批投影、MLP 与解码；GQA 组共享页读取和位置恢复；重算完成后释放打分工作页。 |
| 校准混入路径交错和首次编译费用，回答指令与线上不一致 | Native/InfoFlow 分批校准，单 token 重访测可复用阶段费用，保留首次执行费用，使用与线上相同的回答指令。 |

同 4 个训练状态、并发 4 的 GQA 改造配对中，InfoFlow 解码从 **40.45 降到 27.20 ms/token（−32.76%）**，答案质量标签相同。对齐线上回答指令后的最新校准为 Native **20.20**、InfoFlow **25.47 ms/token**，平均质量差接近零。主队列使用数据文件中的 `evaluation_policy`；随后四状态更新得到 `deployment_policy`，没有重复主队列。InfoFlow 的独立块重访确实减少了计算 token，但冷建、打分、重算和额外解码仍要付费；主队列自动路径仍选择 Native，**尚未取得 InfoFlow 的端到端净收益**。

按现有来源块粒度，改进前队列同会话重访原文占输入的 10.68%（MT-RAG）和 2.45%（MultiDoc2Dial）。这是已发生的整块重访，不包括其他跨会话或部分跨度共享。上下文变短后，可省的 prefill 变少；固定生成模型的解码和辅助编码成为更大的费用项。整体 GPU 时间下降主要来自减少重复生成及其历史成本，不能全部归于 KV 复用。

完整指标、题目清单、校准资产、配对范围和实现版本见 [cooperation_optimization.json](../../results/cooperation_optimization.json)，改进前参照见 [cooperation.json](../../results/cooperation.json)。主结果保留在容器 `runs/cooperation2/tiered/`、`tiered-md/`，缓存配对在 `cache-attribution/`。本轮没有重跑 Loong 和 VersionQA；以下保留已有公开历史结果。
