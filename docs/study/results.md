# 当前评测结果

## 连续真实会话：本轮协同改进

固定 Qwen3-32B BF16 和辅助权重；每个 benchmark 选择 4 个真实会话、各前 5 个相邻问题，共 20 题，并发 4。各方法使用自身已提交历史（P3），保留没有重访的轮次。每个方法/数据集冷启动一次，会话内不清缓存。普通问答仍使用检索、常规拼接和 SGLang Native。

所有队列均交付并完成评分 20/20。质量乘以 100；完整 P95 包含排队、检索、辅助编码和回答。GPU/Host 为在线阶段物理驻留内存的时间积分，评分费用另计。

### 同证据缓存归因

固定实际证据成员、问题、已生成历史和到达偏移，比较语义顺序 Native 与缓存成本排列/需求保留。两路冷启动，使用贪心生成，冷建费用计入执行。配对采用 `b69b60f` 的真实输入轨迹；最终队列为 `1958bda`，两者的缓存执行实现相同。这里的 P95 从输入就绪开始，区别于上表完整 P95。

|---|---|---:|---:|---:|---:|---:|---:|

MT-RAG 的 prefill 减少 **1.68%**，新增计算页减少 **1.60%**，活动 KV 峰值减少 **3.85%**；总驻留池仍达到 8 GiB，执行 P95 基本持平。MultiDoc2Dial 没有明显缓存收益。其配对 F1 为 19.2995 / 19.2924；MT-RAG 两路 8/20 个答案完全相同，这组缓存配对没有单独运行官方质量评分。主队列的官方质量已完整评估。

### 机制落实与剩余问题

- 跨轮需求由未完成 Need、合法来源和已发生的重访共同决定；条件/版本改变或会话结束释放相应优先级。历史跨度补入新召回，不挤占新召回的首批名额。
- 保留原文在历史/问题前的编排，短引用头随同一来源前缀保持一致；相同集合优先沿用可复用的 Native 排列。
- InfoFlow 合批独立块投影与 MLP，位置变换跨层复用，拆分长 KV 注意力并共享长度档解码图。4 个训练状态的当前校准为：Native prefill 0.107 ms/token，独立块构建 0.221，打分 0.579，重算 0.302；Native / InfoFlow 解码 18.55 / 25.25 ms/token。近似质量损失为 F1 0.0190，纳入自动选择。
- 总体上下文投影使用新增共享页、请求私有页与临时页的预算，共享驻留按物理节点去重，替代按并发数均分 token。原生调度器执行实际准入。

本轮自动路径全部选择 Native。InfoFlow 的独立块构建和打分仍有成本，短会话里没有获得实际净收益；没有强行开启近似复用。当前主要成果是跨轮闭环及更好的完整问答结果，**缓存的独立收益仍有限，尚未证明显著缓解显存瓶颈或提高并发容量**。后续重点是增加真实重访的可共享前缀长度，以及减少 MT-RAG 为更多证据付出的编码和生成费用。

完整指标、题目清单、实现版本、来源重访与校准值见 [cooperation.json](../../results/cooperation.json)。逐题答案与来源留在容器 `runs/cooperation/accepted/`；基线为 `runs/cooperation/before/`。本轮未重跑 Loong 和 VersionQA，以下保留其已有公开历史结果。
