# 核心机制修正与 20 题评测

固定 Qwen3-32B，四个 benchmark 各选 20 题，普通文档问答、ContextKV、LlamaIndex 使用相同题目。本轮完成任务完整性、语义集合效用与缓存成本联合选择的实现、辅助头训练和端到端对照。普通文档问答与 LlamaIndex 各交付 80/80，ContextKV 交付 79/80。MultiDoc2Dial 与 MT-RAG 同时提高质量和速度；VersionQA、Loong 仍低于基线。

## 本轮机制与训练

| 环节 | 当前实现 |
|---|---|
| 任务完整性 | 问题级总体覆盖头独立于 count/sum 等运算分类；完整总体任务按真实 ANSWER 窗口决定直接回答或分包读取。查询与可见历史先编码，文档目录随后编码；完整原问题决定语义，辅助 Need 与条件作为提议。 |
| 证据集合 | 在 Jina 共享语义表示上学习集合效用，包含均值、最大值与成对交互。集合头 19,681 参数，以固定生成模型的真实答案增益训练；保留结构依赖，移除错误 Need 片段对集合剪枝的硬限制。 |
| 文档计算 | 语义投影返回原文行号，字段投影返回词区间；CPU 恢复来源、执行已识别的筛选与聚合。来源包决定执行覆盖，模型决定实际字段和运算。JSON 输出额度与最终证据额度分开。 |
| 上下文与缓存联合选择 | 一次获取候选来源的 Native 前缀、GPU/Host 驻留和成本系数；集合选择同时考虑答案效用与获取成本，并可将同一证据集合排序为已驻留前缀。停止头计入已选集合的回答成本。 |
| 执行费用 | Native 与 InfoFlow 比较完整获取费用；Host 搬运先用与 worker 一致的初值，随后用实测更新。来源窗口有独立地址，避免不同切片共用错误 KV 身份。 |

方法来源和适配范围见[方法依据](../references.md)，调用链见[架构](../architecture.md)。

## 缓存协同配对

从训练集取一个六来源问题，先执行原顺序请求建立 Native 前缀，再比较不使用缓存状态的逆序和根据驻留状态恢复的顺序。两个比较请求证据集合相同、输入均为 2378 token，输出上限均为 128 token。

| 请求 | 模型请求耗时（秒） | GPU 命中 token | 实际 prefill token |
|---|---:|---:|---:|
| 共享的首读 | 2.596 | 0 | 2378 |
| 不使用缓存状态，证据逆序 | 2.619 | 0 | 2378 |
| 缓存状态参与编译，恢复驻留顺序 | 2.379 | 2368 | 10 |

复读请求 prefill 减少 99.6%，模型请求耗时降低 9.2%；计入共享首读后的两请求总耗时降低 4.6%。这里计时覆盖 HTTP/引擎请求，不包含此前的缓存快照、选择与编译，因而不等同于完整问答 P95。Host 回载为零。这组结果验证上下文排列利用 Native 驻留的收益，未测得新的 InfoFlow 加速结论；此前 InfoFlow 配对保留在[已存指标](../../results/method-review-20261113.json)。

benchmark 中输入规模、答案长度、上下文选择和缓存命中同时变化，表中的整体 P95 改善不能全部归给 KV 复用。

## 已观察到的剩余问题

1. **版本需求未被可靠保留。** `versionqa-043<::>1` 请求 22.14.0，回答引用 23.11.0；`versionqa-057<::>1` 请求 15.14.0，仍引用 23.11.0。另有方法级稳定性被模块级描述替代。应优先修正查询版本意图与字段支持的衔接，不能靠扩大阅读量解决。
2. **任务监督的细粒度泛化仍不足。** Loong 财报分类题 `3a18a20b-95f1-4bfc-9f5b-ebd1496dffa0` 被辅助头预测为 `min`，subject 只有一个字。最新原问题优先的提示修正经单题检查，仍未使投影稳定完成。总体覆盖头准确率提高，不代表任务、字段和运算关系已正确。
3. **长文总体阅读的单位收益偏低。** Loong 已读约 49.6 万输入 token，质量仍落后。下一步要改善范围内字段定位与语义投影，将必要来源转成可用事实，而不是继续增加阅读和归约轮次。
4. **集合与停止监督覆盖较小。** 当前集合训练 24 个状态、停止训练 12 个状态。它们已接入真实答案与成本，但跨版本和财务资料的泛化还不足。应针对这些通用能力补监督，不添加题目特例。
5. **非前缀执行尚未体现端到端优势。** 当前自动决策可以选回成本更低的 Native；已有 InfoFlow 实测减少 prefill，但打分与执行开销仍高。应先降低此路径的实际费用，再扩大使用。

本轮三个方向的代码、辅助资产与少量端到端对照已交付。MultiDoc2Dial、MT-RAG 的本批结果超过“同质量 P95 降低 15%”幅度；VersionQA、Loong 未达到目标，因此课题整体质量与性能验收仍未完成。

完整轻量指标、同题 ID、评分口径、训练摘要和已付迭代费用见 [20 题结果](../../results/core-mechanism-20-20261113.json)。批次结果来自本轮实现迭代，Loong 最后完整批次代码为 `aa43d27`；之后 `f1c5189` 的提示修正只做单题诊断，没有把诊断混入表中的 20 题结果。逐题答案、来源及训练资产保留于容器 `runs/current/core-20` 和 `models/shared-*`，模型不随代码同步。
