## 机制与训练交付

- 查询：Qwen Embedding 查询侧 LoRA、任务/条件/版本/Need 共享头，RCEM 点对齐、普通查询保持与成对距离对齐；190 个训练状态、39 个开发状态。
- 证据：范围优先混合检索、Jina 作者跨批共享重排、字段/来源头、相对无证据回答的集合效用；54 个训练状态、23 个开发状态，Jina 骨干冻结。
- 文档计算：带原文地址的投影、筛选、连接、CPU 聚合与版本前后配对。普通问答样例没有额外 READ/REDUCE 调用。
- 停止：共享证据表示上的 full-width Q(λ)，34 个训练轨迹、13 个开发轨迹，标签包含真实最终答案及执行费用。
- KV 协同：SGLang 内独立块、全局 RoPE、作者查询 L2 重要度、私有稀疏覆盖和原生 GPU/Host 页池；实际请求携带后续来源需求，执行回执进入下一次决策。

作者源码与适配区别见[方法依据](../references.md)。RCEM 未找到公开作者训练代码；OptiSet 作者仓库尚未发布训练实现，两者按论文机制适配。

## 本轮修复与结果判断

完成 Jina 跨批分数合并、OptiSet 相对效用标签、Stop-RAG 多步备份、InfoFlow 注意力范数，以及单位、去重、版本对应修正。移除无消费者的变化摘要接口和集合采集成本明细。评分只保留最终分量，删除逐词、逐候选评分数组。

小跑发现并修复了引擎重启后丢失实测成本的问题：校准资产保存少量成本系数，每个请求一起提交，后续实测继续更新。公开 8 题的结果包含修复前一次较慢的 InfoFlow 选择；真实历史 2 轮已加载该资产，全部交付，完整响应 P95 为 12.91 秒。离线评分已使用 GPU 5，其他进程沿用指定的 GPU 4–7。

当前同题结果尚未达到质量提升或响应加速目标。主要问题是集合选择仍保留过多原文，输入达到普通问答的约 4.7–15.9 倍，辅助编码和生成开销增加；现有小规模训练没有使集合效用与停止策略稳定优于常规检索。InfoFlow 的冷建、打分和逐 token 解码开销也抵消了部分 prefill 节省。后续优化应集中在集合效用的训练覆盖与校准，以及非前缀执行的计算效率。

最终指标与训练摘要保存在 [JSON](../../results/shared-encoding-smoke-20261113.json)。逐题答案和来源、辅助模型、训练样本与索引保留在容器；本地仅同步轻量结果。
