# 来源投影与性能优化：2026-11-14 实测

Loong 的完整响应 P95 从 **206.78 秒降到 40.49 秒**，主模型输入减少 **86.29%**，额外 READ 从 **70 次降到 0**。当前质量 **45.25**，高于普通问答的 **30.00**，低于修改前的 **51.50**。主要性能瓶颈已消除，保持原有最高质量仍是后续工作。

固定 Qwen3-32B BF16 与辅助权重，每个 benchmark 沿用相同 20 题、公开参考历史、并发 4。各行使用保留路径的最新实测结果；普通问答基线复用已有同题记录。本轮没有训练、重跑基线或 LlamaIndex，也没有新增缓存微基准。

## 根因与保留的实现

| 根因 | 修改 | 实际作用 |
|---|---|---|
| 总体问题绕过共享证据编码，反复由 Qwen 扫描全文、生成行号，再读取所得材料 | Jina 一次编码合法总体；按文档保留证据，依据查询加权覆盖增益选取原文及依赖；已绑定的统计交给 CPU | Loong 主模型输入 840333 → 115226，额外读取 70 → 0 |
| 单请求正文额度与并发 KV 工作集脱节 | 按活跃请求分配实际 GPU KV 容量，扣除提示与输出，再在正文上限内选材 | 控制一次送入模型的工作量；来源顺序与实际缓存计价一致 |
| 同批短请求等待其他请求全部编码完成 | 每个请求自己的最后一个编码分包结束后立即交付并释放临时表示 | 移除跨请求的额外完成屏障 |
| 小规模集合计算频繁同步 GPU；双线性关系对重复做同一投影 | 7 参数集合头及选择在 CPU；关系、连接和目录匹配共享投影后批量配对 | 保持模型权重与评分公式，减少同步及重复运算 |
| 普通问答解码后续不会消费的数值字段、跨度向量和实体连接 | 普通任务只解码来源支持；计算任务才处理字段、条件和连接 | VersionQA 同为 85 分，P95 25.79 → 22.99 秒，辅助耗时累计 48.06 → 40.17 秒 |
| 显式版本问题编码随后被直接匹配覆盖的目录分数；回答看不到目录轴 | 显式版本直接绑定，保留原问题 token 边界；ANSWER 提供来源声明的版本目录 | 删除丢弃的编码工作；版本存在性、最早/最新问题能使用真实索引元数据 |

总体投影借鉴 [Lin & Bilmes 的查询摘要覆盖思想](https://aclanthology.org/P11-1052/)，在共享证据表示上计算各文档内的代表性。原文地址、表头、限定条件与依赖仍保留。普通可选证据继续使用学习到的集合效用和停止价值。

已删除主模型总体行号扫描、二次选择流程和未消费的证据 token 状态字段。跨文档标题提及分区没有显示质量收益，已撤回。没有按 benchmark 或题目内容增加专用分支。

## 上下文与缓存协同

| Benchmark | 主模型输入 / 输出 token | 额外 READ | GPU 命中 / Host 回载 token | 实际 prefill token |
|---|---:|---:|---:|---:|
| MultiDoc2Dial | 8723 / 2756 | 0 | 960 / 0 | 7763 |
| MT-RAG | 34778 / 4633 | 0 | 1664 / 0 | 33114 |
| VersionQA | 37843 / 1744 | 0 | 2048 / 0 | 35795 |
| Loong | 115226 / 2463 | 0 | 448 / 64 | 114714 |

Loong 最新队列的缓存命中与回载共 **512 token**，占输入约 **0.44%**；性能改善主要来自消除重复读取、缩小主模型实际输入及辅助计算精简。当前不能把这部分提速计作 InfoFlow 的非前缀复用收益。

机制上，KV 驻留费用参与选材，GPU 容量参与总体上下文份额，最终选材顺序与缓存计价一致；引擎仍按真实驻留在 Native 与 InfoFlow 之间选择。本轮队列以冷启动和少重访为主，缓存的独立完整响应收益尚未由这组结果证明。已有同证据缓存配对保存在[此前轻量结果](../../results/completeness-performance-20261114.json)，本轮没有将它重复计为新结果。

## 剩余改进重点

1. **Loong 的事实与关系覆盖。** 每个来源有代表片段不等于每项需求的证据齐全；投影仍可能遗漏低相似度但决定答案的条件或关系。后续应让集合收益直接识别缺失的需求证据和互补关系，保持一次共享编码与原文回答主线。
2. **VersionQA 的辅助耗时。** 质量比基线高 5 个百分点，P95 仍高 6.44%；目录与字段冗余已减少，剩余查询理解、检索、证据编码和生成应按真实关键路径继续优化。
3. **缓存协同的收益范围。** 本轮减少工作量的收益明确，冷队列的复用率很低；缓存层的完整回答收益需要在实际发生跨轮原文重访时衡量，不能用预测节省替代实测。

本轮只做语法检查、调用链审查、必要的双线性等价检查和上述端到端迭代。模型、逐题答案与来源留在容器，仓库保留代码及约 32 KB 的结果汇总。
