# 语义事实与动态决策闭环：20 题评测

本轮完成事实交付、阅读状态、停止监督与并发 tokenizer 的衔接修正，并更新辅助任务头。固定 Qwen3-32B、查询 LoRA 与 Jina 骨干，使用容器默认 Python 和 GPU 4–7。代码提交为 `d074067`、`11d6914`。

## 已完成的实现

| 环节 | 本轮修改 |
|---|---|
| 事实进入最终回答 | 字段名、值、单位、限定文本与原文地址一起交付；重复字段和限定共享短 ID。年份等限定不再只保留坐标 |
| 阅读与继续决策 | 每次扩展后先完成所需读取和 CPU 计算，再用实际事实决定继续或回答。已有投影复用，新增来源增量读取 |
| 完整性与原文选择 | 只有完整计算关闭对应需求；未完成计算保留原文选择通路。最终请求按实际结论和原文重新计量 |
| 来源窗口 | 同一来源的不同窗口全部保留，相邻窗口合并；字段绑定按真实覆盖范围取原文 |
| 训练与线上 | 字段标签映射到预测 Need；集合/停止采集复用线上执行器、结论及成本；任务头训练保留 Need 与冻结检索空间的对齐 |
| 并发编码 | 每个编码线程持有自己的 tokenizer 状态，修复并发的 `Already borrowed` |

没有新增 benchmark 或题目专用规则。方法与调用链见[架构](../architecture.md)。

## 各 benchmark 的结果

每项独立使用 20 题，并发 4，种子 42，公开参考历史。普通文档问答与 LlamaIndex 复用已有同题结果，题目 ID 集合已核对一致。普通文档问答流程为“问题 → 检索 → 常规拼接 → SGLang Native → 回答”。

前三项质量乘以 100，Loong 为作者百分制；指标分别为 token F1、MTRAGEval harmonic、VersionQA accuracy、Loong reference score。完整 P95 包含检索、辅助处理、必要计算、排队与生成。GPU/Host 占用积分为整批驻留内存乘时间，裁判费用单列于 JSON。

## 结果解释与下一步

本轮是混合结果，整体质量/性能目标尚未达成。相对普通文档问答，MultiDoc2Dial 与 MT-RAG 分别低 1.66、3.16 分，P95 分别降低 30.8%、40.6%；质量不同，不能据此宣称同质量加速。VersionQA 较此前 ContextKV 的 50 分提高到 60 分，仍低于基线 80 分。Loong 最终交付较此前 ContextKV 的 24.25 分提高到 35.50 分，但包括补跑的 GPU 占用积分约为基线的 8.2 倍。

当前优先问题：

1. **任务范围与字段语义。** 任务预测仍会先限制合法来源；一旦排除正确来源，后续候选扩展无法找回。程序结构完整也不代表实体、时期和字段理解正确。
2. **集合效用与剩余需求的衔接。** 控制器现已使用实际计算状态，但集合头仍主要使用证据表示、相关性、依赖与成本，没有直接表达已知事实和剩余语义需求。当前小规模监督未能稳定保留普通问答所需证据。
3. **长文语义读取的有效性。** Loong 完成交付使用约 50.2 万输入 token，正确性仍有限；应优先改善任务—字段—事实对应和读取后的结论利用。
4. **协同收益归因。** 当前缓存成本已进入选择与停止，仍需在质量稳定后用少量同上下文配对区分上下文减少与 KV 复用的贡献。

本轮批次位于容器 `runs/current/semantic-20`，两题补跑位于 `runs/current/semantic-repair`。轻量质量、成本、评分与辅助训练摘要见[本轮 JSON](../../results/semantic-state-20261113.json)。此前结果保留在[结果目录](../../results/README.md)，不与本轮混合计分。
