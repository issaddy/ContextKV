# 方法源码审查与小跑结果

固定 Qwen3-32B，沿用容器默认 Python 和依赖，仅使用 GPU 4–7。本轮完成源码核对、机制修正、集合头重训和停止轨迹刷新；四个 benchmark 各 2 题全部交付并评分。评测代码为 `d37fa4e`，普通文档问答与 LlamaIndex 复用相同题目的已有结果。

## 方法核对与修正

作者源码、论文与项目入口逐项对应于[方法依据](../references.md)。

| 环节 | 核对结果与本轮处理 |
|---|---|
| Qwen Embedding＋RCEM | 核对末 token 池化、归一化、会话点对齐和成对距离对齐；查询 LoRA 与文档冻结空间分离。关闭文档编码无用的 KV 输出，本轮沿用查询权重。 |
| 范围优先混合检索 | 核对合法来源过滤在 BM25/稠密 top-k 之前。普通 lookup 不再因误预测的总体标签展开整个文档库；统计计算与显式完整范围继续使用完整目录。 |
| Jina 共享编码 | 核对作者 marker projector、跨批 query 加权 cosine；重排、字段与集合共用表示，已有字段头继续复用。 |
| OptiSet 式集合效用 | 原始无界求和在大候选集上预测出超过 30 的质量增益。改为相对空集合的有界增益、MSE＋列表 KL 和实测 prefill 价格；冻结 Jina 的相关性、一致性及规模训练 81 参数头。剪枝保留已获支持 Need 的来源和依赖。训练使用与采集/线上一致的推断任务表示，冻结编码只计算一次。 |
| TableRAG 式计算 | 核对作者结构入库与 SQL 执行，项目适配为带来源地址的投影、筛选、连接和聚合。CPU 小例完成跨表筛选后的 sum=17、count=1，并保留原文来源。 |
| VersionRAG | 核对先定位版本、再检索内容及章节/字段对应。as_of 由共享查询头根据含有效期的目录选版本 ID，不对时间原文做字符串日期比较；前后版本成对来源已检查。 |
| Stop-RAG | 核对作者 full-width Q(λ) 多步备份。修正冷反事实分支之间的缓存污染和并发会话混用执行回执，按当前证据头刷新真实答案与成本标签后重新拟合。 |
| InfoFlow KV | 核对独立块、全局 RoPE、head 均值后的 query L2 重要度及末两层平均。独立页与私有重算复用 SGLang 页池；输出长度估计排除长度截断样本。 |
| Native／GPU／Host 协同 | 独立块保留按相对 Native 的边际收益估值；实际公共前缀同时登记 Native 需求，同一未来消费者只选择一种表示计收益，共享页容量只计一次。优先级随实测更新，会话结束通过原生 owner 释放需求。 |

RCEM 未找到公开作者训练代码；OptiSet 作者仓库仍未发布训练实现。两者按论文机制适配；TableRAG、VersionRAG 复用结构与执行思路。InfoFlow 的 SGLang 调度、私有覆盖和原生缓存协调由本项目实现。

辅助训练范围：查询 190 个训练状态/39 个开发状态，字段 54/23，均复用已有权重；本轮集合头拟合 34 个有集合监督的训练状态，停止头使用新采集的 16 个训练状态/4 个开发状态、40 次真实答案。生成模型与 Jina 骨干保持冻结。

## 非前缀缓存配对

使用训练集中一个 6 来源状态，先原顺序、再逆序；Native 与 InfoFlow 各自从冷缓存开始。每次输入 2378 token，输出均达到 128 token 上限，重算比例 15%。这项配对衡量相同输出工作量下的完整执行费用。

| 执行方式 | 请求 | 完整耗时（秒） | 实际 prefill 工作 token | GPU 命中 token | 证据重算 token |
|---|---|---:|---:|---:|---:|
| Native | 冷建首读 | 2.62 | 2378 | 0 | 0 |
| Native | 原文块逆序复读 | 2.62 | 2378 | 0 | 0 |
| InfoFlow | 冷建首读 | 5.72 | 2954 | 0 | 318 |
| InfoFlow | 原文块逆序复读 | 5.14 | 834 | 2120 | 318 |

InfoFlow 逆序复读命中 2120 token，prefill 工作比 Native 减少 64.9%，但完整耗时为 5.14 秒，Native 为 2.62 秒。计入首读冷建后，两次请求合计为 10.85 秒与 5.24 秒。非前缀复用已生效；当前打分、稀疏执行与自定义解码的总开销仍高于这组短上下文的节省。本轮没有施加 Host 回载压力，Host 命中均为 0。

## 仍需改进的重点

1. **查询头的任务结构泛化。** Loong 的两题被切成 14 和 11 个 Need；中文完整列举题的 Need 全部误判为 lookup，锚点包含“根据”“作”等片段。非数值全体推理和完整列举仍没有可靠地转成正确任务与完整证据需求。这是已观察到的能力缺口。
2. **集合效用的表达能力与跨领域监督。** 轻量头消除了无界外推，Need 支持约束保住已有绑定，但三个集合特征无法完整表达高阶互补关系；错误 Need 又会影响剪枝。Loong 质量从 75 降至 20，表明减少输入不能替代完整证据。MT-RAG 质量也仍低于普通 RAG。
3. **InfoFlow 执行开销。** 缓存命中和 prefill 节省已测到，完整响应仍未受益。应优先减少非前缀路径的打分、重算和逐 token 解码成本，再扩大适用范围。

本轮 MultiDoc2Dial 质量改善，VersionQA 同质量下比普通 RAG 的 P95 低 38.7%；其余结果不支持“整体已优于基线”的结论。后续应修正任务监督和全体证据选择，再优化非前缀执行成本；不继续扩大实验格数。
