# 完整性与性能优化：2026-11-14 实测

本轮修正来源身份、总体覆盖和上下文预算，并清理已定位的分词与请求调度开销。固定 Qwen3-32B 权重、精度和生成参数；每个 benchmark 使用同一组 20 题、公开参考历史、并发 4、种子 42。主表各行均完成 20/20。

MultiDoc2Dial 已同时提高质量、降低延迟和资源积分；MT-RAG 的延迟基本对齐普通问答。Loong 质量明显提高，但全量读取仍很慢；VersionQA 也仍有性能差距。当前不能将整体性能问题标为已解决。

## 根因与实际修改

| 根因 | 证据 | 当前实现 |
|---|---|---|
| 线程初始化深拷贝整个 tokenizer | 单次首次检索 7.47 秒，其中完整 tokenizer 深拷贝约 3.79 秒；重复检索仅 0.52 秒 | 只复制可变底层 tokenizer，共享配置和词表映射；同一首次检索降至 4.48 秒 |
| 短来源反复分词 | 50 个候选的分窗触发约 7128 次分词、耗时约 1.83 秒 | 能直接容纳的来源一次分词后直接保留 |
| 控制器阻塞请求事件循环 | 证据选择、GPU 张量同步和停止特征在异步请求线程执行；没有待扩展候选也计算停止摘要 | 工作线程执行选择和继续决策；候选耗尽直接回答 |
| 来源切分后丢失身份 | 随题文档标题为空，同名财报的数值片段无法明确关联公司；关系读取看不到完整文档目录 | D1/D2 等稳定文档编号、原文标题及 128-token 开头构成身份目录；片段保持文档关联 |
| 总体意图被末端实体压过 | 分类、分组、入向/出向关系问题被判为局部查找，最终只保留一个来源 | 覆盖头改用整段当前问题的 token 均值；补充独立领域的双语覆盖监督 |
| 压缩后的实际输入膨胀 | 多个原文片段重复标题和引用头；32K 正文方案出现一次窗口耗尽 | 连续同源片段共享标题与引用 ID，省略处标记；预算与请求共用正文渲染 |
| 读取与 KV 资源预留脱节 | 行号选择沿用 8192-token 输出上限；引擎将该上限计入资源安排 | 按完整行号数组及 XGrammar 实际固定 JSON 格式计量输出份额；原文需求随请求交给缓存层 |

总体覆盖头使用 382/95 个训练/开发状态，开发准确率为 **96.84%**。只更新该头；Qwen3-32B、查询骨干及 LoRA、其他任务头、Jina 与字段/集合头、停止头保持固定。新增监督来自通用分类、分组和依赖关系问题，没有使用评测题目作为训练标签。

32K 模型窗口与 32K GPU KV 容量不代表应把单请求正文填到 32K。实测扩大正文后长请求影响并发，故当前恢复 **16K 正文份额**。超出份额时只压缩必要的尾部片段，其余原文保留；累计预算仍计入全部读取和最终回答。

## 同题基线比较

普通文档问答为“问题 → 检索 → 常规拼接 → SGLang Native → 回答”。前三项质量乘以 100；Loong 为作者百分制。完整 P95 包含排队、检索、辅助编码、必要计算与回答。资源为整批物理驻留内存的时间积分，包含辅助模型；离线评分成本单列在 JSON。

| Benchmark | 方法 | 质量 | 完整 P95（秒） | 输入 / 输出 token | GPU / Host GiB·s |
|---|---|---:|---:|---:|---:|
| MultiDoc2Dial | 普通文档问答 | 17.93 | 17.72 | 20869 / 4673 | 2454.4 / 692.2 |
| MultiDoc2Dial | ContextKV | 29.44 | 11.66 | 8076 / 2557 | 1902.0 / 511.2 |
| MT-RAG | 普通文档问答 | 56.97 | 30.53 | 86846 / 6360 | 4262.8 / 1200.2 |
| MT-RAG | ContextKV | 59.52 | 30.76 | 34778 / 4792 | 4037.8 / 1138.2 |
| VersionQA | 普通文档问答 | 80.00 | 21.60 | 51567 / 1795 | 2404.7 / 661.1 |
| VersionQA | ContextKV | 80.00 | 27.15 | 33842 / 1983 | 2562.1 / 739.5 |
| Loong | 普通文档问答 | 30.00 | 41.37 | 101394 / 2614 | 3624.8 / 972.1 |
| Loong | ContextKV | 51.50 | 206.78 | 840333 / 10949 | 17762.9 / 4957.9 |

相对同轮普通问答：

- MultiDoc2Dial：质量 **+11.51 个百分点**，P95 **−34.22%**，GPU 积分 **−22.51%**。
- MT-RAG：质量 **+2.55 个百分点**，P95 **+0.74%**，GPU 积分 **−5.28%**。
- VersionQA：质量持平，P95 **+25.68%**，GPU 积分 **+6.54%**。
- Loong：质量 **+21.50 分**，P95 约为基线 **5.00 倍**，GPU 积分约 **4.90 倍**。

MultiDoc2Dial、MT-RAG 及三项基线来自 `window-20/2b24342`；VersionQA 当前方法来自 `dispatch-20/18a7dd0`；Loong 基线为 `compact-20/3277d9f`，当前方法为 `schema-fixed-20/5b655c4`。前三项这轮实际输入均低于 8K，没有重复来源片段，未触发后续恢复的 16K 正文上限；文档片段渲染和输出份额修正单独在 Loong 重测。

## 缓存协同配对

同一道问题、6 份相同证据与历史，每条分支清空缓存后按相同逆序来源预热。Native 两条分支的预热相同；InfoFlow 另需建立独立块。单 token 输出用于观察预填充与请求编排开销。

| 路径 | 预热（ms） | 单 token 请求（ms） | GPU 命中 token | 实际 prefill token |
|---|---:|---:|---:|---:|
| Native，相关性原顺序 | 260.28 | 271.17 | 0 | 2325 |
| ContextKV，按缓存成本排列 | 267.13 | 40.61 | 2304 | 21 |
| 强制 InfoFlow | 1493.17 | 425.56 | 2120 | 728 |

成本驱动排列选择了 Native 精确路径，单 token 请求耗时减少 **85.02%**，prefill 减少 **99.10%**。

| 路径 | 完整回答（秒） | 输出 token | F1 |
|---|---:|---:|---:|
| Native，相关性原顺序 | 5.77 | 297 | 8.53 |
| ContextKV，按缓存成本排列 | 6.39 | 343 | 6.25 |
| 强制 InfoFlow | 18.78 | 489 | 5.34 |

这次完整回答中，缓存排列的输出更长、F1 更低，完整响应也没有加速。当前配对证明了预填充复用收益，尚未证明同质量下的完整响应收益。InfoFlow 在该短请求中仍不如 Native。本轮没有增加 Host 压力实验。

## 迭代与失败记录

本轮共执行 17 个方法/版本批次，每批同一 benchmark 的 20 题；共 340 次逐题执行，333 次交付、7 次失败。独立题目仍为四个 benchmark 各 20 题。全部批次、逐题分母、失败费用与评分费用保存在[轻量结果](../../results/completeness-performance-20261114.json)，不把重复运行计为新增独立样本。

| Loong 迭代 | 交付 | 完整分母质量 | 完整 P95（秒） |
|---|---:|---:|---:|
| 来源身份与覆盖修正 | 20/20 | 50.25 | 154.73 |
| 扩大正文到 32K | 19/20 | 50.75 | — |
| 共享标题、恢复 16K | 20/20 | 56.75 | 272.37 |
| 行号输出预算：格式计量有误 | 14/20 | 39.25 | — |
| 按实际 JSON 格式计量 | 20/20 | 51.50 | 206.78 |

32K 正文方案已撤回。行号输出的第一次预算按无空格 JSON 计算，但 SGLang/XGrammar 固定格式默认包含空格，导致 6 次截断；代码已统一格式。没有用成功子集替代完整队列指标。最后一轮相对共享标题版本 P95 降低 24.08%，质量也下降了 5.25 分，不能称为同质量提速。

## 剩余的主要问题

1. **Loong 的完整性仍依赖过多主模型扫描。** 下一步需要在结构索引上投影字段、实体和关系，保持总体覆盖后再交给 Qwen；单纯改变上下文大小或输出上限不足以解决成本。
2. **任务与字段语义仍不稳定。** 长指令的 Need 片段、数值区间分类、关系方向和版本目录范围仍有错误；正确读到值也可能产生错误分类。不能靠增加读取次数解决这些问题。
3. **VersionQA 的辅助开销尚未抵消。** 实际辅助耗时累计约 41.59 秒，普通问答约 38.14 秒；当前整批质量相同、P95 更高。异步调度修复消除了阻塞路径，但这轮没有证明其单独带来 P95 改善。
4. **缓存编排的质量影响尚未建模。** 集合收益主要评价成员，改变材料顺序仍可能改变答案；预填充节省应与完整回答质量和输出长度一起评价。
