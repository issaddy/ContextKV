# 动态流程优化与小批评测

本轮修正任务理解、证据选择、文档计算和缓存收益学习之间的衔接。固定 Qwen3-32B；使用默认 Python 和 GPU 4–7。已撤回实测降质的整段历史重排输入，当前保留任务聚焦重排、完整事实交付、紧凑来源地址和缓存监督修正。

## 当前保留的机制

| 环节 | 实现 |
|---|---|
| 多轮上下文 | Qwen 共享编码理解历史，Jina 使用当前问题及共享任务线索；任务、字段与集合复用已有表示 |
| 可选扩展与必需计算 | 停止头决定是否继续获取证据；选材结束后执行必需计算。问题级总体范围传入文档程序 |
| 事实与完整性 | 各批次已提取事实持续保留；未解决条件以 incomplete 状态交给回答。完整计算才输出聚合值，跨轮复用完整结果 |
| 来源协议 | 字段地址为 `[source_id, first_word, last_word]`，文档实体为 `[source_id]`；CPU 恢复原文坐标 |
| 关系计算 | 投影同时带入筛选、连接、分组所需的源列；lookup 独立于聚合分组；最终聚合统一解析数值及单位 |
| KV 联合决策 | 选材按真实驻留估计获取成本；停止训练中的预热、报价、执行使用相同分支命名空间，覆盖 auto 政策下的 Native 或 InfoFlow |

没有新增按 benchmark、产品名称或特定版本号执行的规则。方法依据见[复用说明](../references.md)，动态调用链见[架构](../architecture.md)。

## 投影协议与关系计算检查

整批中一题因冗长字段地址 JSON 截断而失败。紧凑地址输出后，又识别并修正了关系执行中的两处缺口：未输出的筛选列未被带入投影、lookup 被当作聚合分组处理。最终对该题单独检查：

| 结果 | 数值 |
|---|---:|
| 完成交付 | 1/1 |
| 作者得分 | 10/100 |
| 完整响应 | 45.95 秒 |
| 输入 / 输出 token | 34199 / 2018 |
| GPU / Host GiB·s | 3682.5 / 1024.6 |

该检查验证执行链已经走通，仍没有形成高质量答案。它不作为新的 20 题 benchmark 结果，也不覆盖整批试验中的失败费用。短地址、源列绑定和 lookup 语义均是通用协议与关系计算修正。

## 辅助资产与剩余问题

字段训练使用 54/23 个训练/开发状态，集合训练使用 24/6 个状态并复用已有 180 次答案标签。停止训练使用 12/4 个状态；两种重排输入各刷新一轮，共采集 64 次监督答案。当前权重对应恢复后的任务聚焦输入。查询权重、Qwen3-32B 和 Jina 骨干保持不变。

剩余重点：

1. **任务与字段的语义准确性。** 执行通路已能交付事实，但投影检查仍只有 10 分；应改善需求、字段、条件和实体的对应，而非继续添加题目特例。
2. **集合与停止收益的泛化。** 本轮减少输入同时降低质量，表明当前小规模监督下的效用预测不足以稳定控制取舍。
3. **长文阅读的有效信息密度。** 试验版 Loong 输入 46.2 万 token，仍低于基线质量；更多阅读没有充分转化为正确结论。
4. **整体目标尚未完成。** 当前 MultiDoc2Dial 复测显示同质量附近的 P95 收益，其余三项需要在后续实质优化后验证。
