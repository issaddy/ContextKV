# 回答质量迭代与当前结果

本轮修正了证据效用误判、原文切分、明确版本绑定及表格字段接口，并更新集合头和停止头。固定 Qwen3-32B、查询模型及 Jina 骨干。四个 benchmark 各 20 题，公开参考历史，并发 4，种子 42；与已有基线的题目 ID 集合一致。

## 根因与修改

| 环节 | 实际问题 | 修改 |
|---|---|---|
| 证据集合 | 正确“何时申请”段落的 Jina 相关性为 0.495，却被集合头赋予低于无关儿童申请标题的收益；后者相关性仅 0.068 | 用相关性、语义覆盖、重复程度、字段支持及已完成 Need 预测集合增益。集合头参数从 19681 降到 225 |
| 上下文组织 | 固定 8 行切分使原文被拆成短标题或不完整片段；首批编码可能尚未看到关键内容 | 按 token 额度和原文边界分窗，保留表格依赖。合并重叠任务引用，保留原始标点 |
| 版本范围 | 问题明确写出 22.14.0，任务头仍预测 current，旧版本在检索前被排除 | 将明确出现的目录版本 ID 绑定到来源，优先于默认意图 |
| 表格计算 | 长表 ID 输出截断；表内筛选引用未声明字段 | 使用短表 ID，筛选直接引用原文列号；CPU 将未输出的筛选列带入投影 |
| 最终交付 | 不完整计算可再次触发整个文档总体读取；最大输出额度也会触发预算拒绝 | 已检查范围复用已有观察，只读取未检查原文；输出额度按剩余预算分配，语义读取保留最终输出空间 |

两道申请时间题已选中正确段落；两道明确版本题也得到正确答案。Loong 的预算失败仍未解决，不能把局部修正等同于完整终端预算已经接通。

## 长文预算问题

失败题要求按财报中的预付款项划分公司。三个后续尝试均使用同一题：

| 尝试 | 交付 | 输入 / 输出 token | GPU / Host GiB·s |
|---|---:|---:|---:|
| 扩大语义分包（已撤回） | 0/1 | 111604 / 1593 | 4121.2 / 1152.3 |
| 按剩余预算分配输出 | 0/1 | 114600 / 9372 | 16400.1 / 4584.3 |
| 复用已检查来源的观察 | 0/1 | 126463 / 2542 | 5666.9 / 1584.2 |

整批与这三个尝试累计 Loong 输入 1017375、输出 22306 token，GPU / Host 积分 43245.5 / 12176.2 GiB·s。三个尝试没有增加独立题目分母。

最后一次尝试在支付 126463 输入、2542 输出 token 后，剩余额度无法容纳下一次输入。执行器能裁定单次输出上限，但继续读取前仍未把完整结论输入与终端回答费用纳入统一决策。这是代码层面尚缺的预算衔接。

## 当前资产与下一步

集合训练保留 22 个训练状态、5 个开发状态和 158 个答案标签；候选数量为 3 或 6。用开发损失选择第 33 轮权重。停止训练保留 11/4 个训练/开发状态、33 个答案标签。字段头、查询任务头、查询 LoRA、Jina 骨干和 Qwen3-32B 本轮均保持固定。训练文件逐状态写入有效标签，不增加过程日志。

必要 CPU 检查确认空集合增益为零且梯度有限、未输出筛选列正确得到求和 7、已检查的不完整观察不会再次触发总体读取。没有扩展单元测试套件。

接下来优先完成：

1. **集合收益与停止校准。** 线上初始候选通常为 24，训练候选只有 3 或 6。平均选入来源从 MultiDoc2Dial 的 4.15 增至 10.25、MT-RAG 的 4.25 增至 16.0、VersionQA 的 5.55 增至 11.75。需要学习新增信息的收益何时饱和，减少无效扩展。
2. **完整终端费用参与读取决策。** 读取前计入已有事实、下一次读取及最终结论输入的费用；预算内选择继续或交付已有事实，保持总体未完成状态。
3. **关系与范围的语义质量。** VersionQA 仍有旧版本构造函数字段混淆、最早版本未正确定位；Loong 仍有判决案由筛选和引用链错误。更多原文并未转化为正确关系结构。

原始逐题答案和来源位于容器 `runs/current/quality-20`；三个补测分别位于 `quality-repair`、`quality-budget`、`quality-observations`。代码和[轻量结果](../../results/quality-iteration-20261113.json)已同步，模型留在容器。
