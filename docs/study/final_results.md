# ContextKV 本轮训练与评测结果

本轮完成固定 Qwen3-32B 下的辅助训练、四个 benchmark 各自 50 题的三方法主比较，以及多轮实际历史和少量缓存配对。Loong 的完整队列质量比普通问答高 8.60 分、比 LlamaIndex 高 5.40 分，达到 +5 分的质量差门槛；其交付率为82%，阅读开销高。四个 benchmark 尚未形成整体质量与实际成本优势，同质量完整响应 P95 降低15%的目标没有达成。

## 配置与指标

| 项目 | 本轮设置 |
|---|---|
| 模型 | Qwen3-32B，固定权重，BF16，关闭 thinking |
| 设备与环境 | GPU 0–3；容器默认 python3 |
| 任务 | 每个 benchmark 独立 50 题；种子 42；同 benchmark 共用 task ID |
| 主比较 | 并发 4；作者参考历史。普通问答为检索、重排、窗口拼接、Native 缓存、回答；LlamaIndex 为历史凝练与 compact/refine；ContextKV 为预算阅读、事实复用与需求缓存 |
| 多轮比较 | MultiDoc2Dial、MT-RAG 各方法自身真实历史；会话内依次推进 |
| 容量 | 模型窗口 32,768；Native GPU 32,768 / Host 61,056 token；需求保护 8,192 token |
| 辅助链 | 查询侧 LoRA + 混合召回 + 发布版重排；teacher 任务解释；实测动作收益与成本；ContextPilot 排列 + next_use 租约 |
| 评分 | MultiDoc2Dial 作者 F1/EM；MT-RAG 作者 MTRAGEval；VersionQA/Loong 作者 rubric。模型评分使用本地固定 Qwen，并非远端榜单 judge |

质量列统一以 0–100 显示，Loong 保留作者百分制；各数据集分别比较。完整队列质量将未交付记为零；已交付但缺评分的项目单列。完整响应包含排队、检索、辅助处理、READ/REDUCE、回答及控制。完整队列 P95 的位置落在未交付项时为“—”；已交付 P95 另列。

## 上下文与 KV 缓存协同配对

固定相同正文、预热、竞争请求和最终问题，两个方法都回答正确。完整链时间已包含保护控制。

| 缓存压力 | 并发 | Native 完整链/ms | 需求保留完整链/ms | 净节省/ms | 最终回答 Native→保留/ms | 被改变的缓存工作 |
|---|---|---|---|---|---|---|
| 低压力 | 1 | 2647.31 | 2644.89 | 2.42 | 118.77 → 118.76 | 相同 GPU 命中 |
| GPU 压力、Host 可回载 | 1 | 5361.15 | 5373.49 | -12.35 | 135.57 → 118.53 | 6,976 Host 回载 → GPU 命中 |
| GPU 压力、Host 可回载 | 4 | 5203.58 | 5225.23 | -21.64 | 135.00 → 119.58 | 6,976 Host 回载 → GPU 命中 |
| GPU/Host 同时受压 | 1 | 13110.82 | 12398.59 | 712.23 | 870.69 → 118.74 | 6,976 重算 → GPU 命中 |

双层压力配对完整链净缩短 5.43%，最终回答 870.69→118.74 ms；预填充 7,056→80 token，GPU 命中 0→6,976。Host 回载两组的最终回答减少15–17 ms，但约18–20 ms控制与链路波动使完整链净变慢。低压力下没有必要增加保护。这个配对体现“实际后续来源需求→保留→减少重算”；不能把主比较的全部质量或延迟变化归因于缓存。

## 已定位问题与本轮修正

| 环节 | 本轮修正 | 仍影响结果的主要问题 |
|---|---|---|
| 证据与历史 | 普通基线真正检索来源窗口；短近期历史与语义历史共同使用；查询 LoRA 接线 | 训练状态集中在 MultiDoc2Dial；任务结构头及支持监督尚不足，不能替代当前默认解释与重排 |
| 动作与费用 | 按动作类型拟合收益树；按唯一实测分支拟合成本；保留真实表示质量差 | REDUCE/GAP 样本少，开发集决策目标未优于直接回答；跨 benchmark 的质量目标不一致 |
| 编译与阅读 | 批量 tokenizer、稳定段缓存、单轮 READ 编译复用；CPU 编译移出服务事件循环；READ packing target 与模型真实窗口分开 | 完整来源阅读调用过多，候选枚举与辅助解释仍消耗时间；长文结构化输出存在截断 |
| 结论与回答 | 复用同一已编译 ANSWER 候选；语义阅读完成后可以回答已有结论与未解决点；归约含前驱证据；group 不再等待数值字段 | 长文部分任务仍不能交付；严格数值需求与不完整提取之间仍有缺口 |
| 缓存协同 | 上下文和 ANSWER 来源消费者驱动租约；Native 实测报价反馈动作；共享页容量与消费者收益去重 | 主模型保存收益必须超过控制费用；Host 可回载场景尚无完整链净收益 |
| 记录与训练资产 | 收益训练使用特征与真实质量/费用；约496.7 MB配对整理为2.23 MB（减少99.55%），不再要求原始上下文和重复分支 | 已汇总各 benchmark 最终指标、有效训练标签与当前查询/收益资产 |

工程闭环已经接通；Loong 取得完整队列质量增益，MultiDoc2Dial 取得较小增益。质量、交付与完整响应的整体优势尚未在四个 benchmark 上成立。下一步应集中于长文有效提取与停止决策、变更检索、动作监督的跨任务覆盖，以及控制开销低于所避免重算的缓存分配。无需再扩展测试格。
