## 优先改进点

1. **B 的尾延迟与完成预算。** 原队列收益 B 提高质量却推高 P95。首轮并发 1 的 E5 最慢直接回答中，进入控制器前的等待中位数为 43.7 秒，滚动决策路径为 1.9 秒。优先用已付步骤账本把下一步的服务时间和排队代价纳入继续阅读决策，并保留对结构化统计直接走 CPU 的路径。
2. **A 的适用事实绑定与归约缺口。** 共题记录中无复用触发，A 的复用收益尚无证据。VersionQA 实例已读出 2019、2024 的 Linux 数值 81 和 101，却因 2024 Windows 材料触发无关缺口而未交付。修正条件原文与来源元数据的匹配后，同一案例的离线来源筛选只保留两个 Linux 版本。后续重点是依据 Need 的条件、版本、字段和已有来源匹配跨轮事实。
3. **C 的净收益覆盖。** 当前少量真实配对不足以覆盖实际前缀长度和重访压力。原生页移动有时可观测，整请求收益仍随排队和回载而变。优先利用现有 READ/ANSWER 回执估计可避免的回载或重算、挤出和控制成本，按实际消费者去重评估边际收益。
4. **评分与资源口径。** 首轮缺分涉及 9 条 MT-RAG、3 条 VersionQA 已交付答案。已修复评分输出预算、原生 schema 和 JSON 解析，第二轮一条已付评分通过原回执恢复。整队列 Native 指标因模型标记失配缺少准备和清理阶段，代码已修正。现有各轨请求窗口的 KV 占用及完整在线窗口的物理占用均有记录。

短队列 E6 的 P95 点估计达到降幅目标。并发 1 的 E1 超过登记的 120 秒上限。原登记的 E1/E6 完整队列配对、独立整队列 P95 区间及完整 Native 采样仍缺，登记验收未完成。
