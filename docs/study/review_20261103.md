## 结论与四个目标

项目已经具备任务证据、结构化阅读、滚动收益决策、独立前缀 owner 和实际训练的完整骨架。当前主要问题是模块间的目标与状态没有完全对齐：训练目标有额外可见信息，阅读结论缺少完整替代语义，B 的停止条件与成本状态失真，C 的实验缺少可观察的跨轮保留机会。继续增加独立模块或扩大参数网格，不能直接解决这些问题。

本轮和后续工作围绕四个目标：

| 目标 | 本轮交付 | 下一阶段判定 |
|---|---|---|
| G1：恢复可解释的正式评价 | 条件化指标、完整 gold 分母、共同子集命名修正 | 原答案离线重评；完整声明 cohort 的质量、完成率、成本共同选型 |
| G2：让阅读计算转化为正确结论 | 缺口关闭、有限归约 DAG、完整 frontier、新旧归约替代、合法 ANSWER | 受控条件/版本/长文计数求和/多跳通过；R0 同输入重放逐步骤对照 |
| G3：提高 A 的实际回答收益 | REMOVE 监督、共享证据归属、可执行负例、可见目标生成 | 固定预算下完整开发 cohort 的质量较当前可行参照提高至少 5 个百分点，随后持出验证 |
| G4：把 B/C 节省兑现成质量 | 缓存状态条件化成本，明确 C 的重访实验与边际价值 | 相同质量下 P95 降低 15%，或相同完整响应/物理容量下达到 G3；两条曲线分别报告 |

5 个百分点和 15% 是下一阶段设定的研究目标，不是本轮模型实测结果。当前源码环境完成机制检查；权重、原始答案和 GPU 运行资产由既有实验环境保存。

## A：任务、证据与 reader

### 本轮修正

1. **撤销条件进入监督与实际解码。** TeacherTaskModel 的 REMOVE 使用 `predicate_span + target_refs`；旧 task_targets 没有标注谓词，decoder 只从 value span 产生条件更新。现在复用 CONDITION_KEY/update/pointer 通道，产生无 value 的 REMOVE，并从 Need 中移除已撤销条件。模型头形状保持一致。代码：[task_model.py](../../training/task_model.py)。

2. **同一原文对多个 Need 的贡献合并。** 旧缺口召回按最后一次出现覆盖 need_ids 和 score。现在共享段保留全部需求归属及最高召回分，进入各 Need 的候选限额。实际扩展阅读合并点复用同一函数。代码：[evidence_pool.py](../../adapters/evidence_pool.py)、[study_retrieval.py](../../adapters/study_retrieval.py)。

3. **删除前提的干预保持可执行依赖。** 旧负例删除 eligibility，却保留依赖它的 step，真实阅读在依赖闭包处中止。现在同时删除依赖该前提的传递分支，剩余证据仍用原始依赖和统一装配路径，能够生成实际答案奖励。代码：[preference_rollout.py](../../training/preference_rollout.py)。

4. **阅读协议审计使用实际可见输入。** 旧教师同时看到 reader prompt 与额外完整原文，存在用隐藏事实写目标的通道。现在目标生成只读取 exact messages；独立核验再读完整来源，评价固定 target 的原文正确性与 `visible_prompt_support`，记录 READ/REDUCE 的 `upstream_errors`。两个阶段分别计量。代码：[reader_audit.py](../../training/reader_audit.py)。

CPU 例中，reader 只见 655000 g，而核验来源另含 D36/666 kg。新协议不会把后者写成前一个输入的目标；错误回溯到实际 READ/REDUCE 步骤。审计结果用于协议诊断，不产生 Qwen SFT 数据。

### 下一阶段机制

A 的主对象是“在当前 reader 上能够提高最终回答的证据集合”，任务提取、支持评分和阅读协议围绕它改进，Qwen 权重保持不变。

先取训练分区的 200 个不同实际状态、开发分区 40 个状态，按会话隔离；每状态构造 4—6 个真实候选集合，覆盖当前集合、补齐必要前提、删去冗余、错误条件/版本以及可执行的前提删除。使用当前 reader 实际生成，采集 800—1200 个训练候选的质量和完整成本。这个规模用于取代 22 答案/5 状态的原型监督。

协议审计分为 READ 原子事实、REDUCE 推理/计算、ANSWER 结论使用三个阶段。对长文先分别统计实体漏提、量值/单位错误、去重错误和最终答案覆盖；对多跳统计桥接实体、下一关系、终端事实与引用链。当前 ANSWER 已携带派生 value/unit/operation 和 Computed 行，分阶段核验分别定位协议错误。

使用固定实际历史的规划器 × 阅读协议四格定位贡献，再运行各格自己的真实历史 P3。task_first+numeric_need_isolation 为协议对照，source_first+共享提取为优化协议；Qwen 权重、解码、预算与评价保持一致。P1 奖励来自固定模型的实际答案，P0 为规划器对照。

## B：有限阅读与质量收益决策

### 本轮修正

**缺口状态统一。** `unresolved_needs` 由后续 support 关闭终端 Need 的旧缺口，合并同一关系的父 claim，区分 temporal_scope。固定扩展、滚动恢复、逐步结果和最终输出使用同一函数。旧逻辑只在最终输出过滤，补检索发生得更早，因而会为已解决问题继续付费。

**归约从无限重写变为有限合并。** 旧超窗分包把所有 child.claims 再拼回相同归约器，输出不收缩时持续重写。现在保留完整分片 bundle：N 个初始包执行一次，后续每个合并节点至少消耗两个 bundle，最多 N−1 个合并节点；不能合并的根组成 forest。CPU count/sum/union/group 继续采用完整 extract 基底。

**有效结论有明确完成与替代语义。** `ReductionState` 记录逻辑步骤、输入基底和全部 frontier，存入最后一个真实步骤结果。完整新基底替代旧子集归约；完成前沿用旧 frontier 和新增 extract。父边仍表示真实事实依赖，历史结果保留。独立分片和未消费输入一起进入答案规划。

**恢复仍按真实物理步骤计量。** 步骤账本按 step ID 更新；恢复逻辑 DAG 重用已有物理节点，不重复累计 token 或步骤数。已完成的模型步骤继续完成来源 prefix 回调和 epoch 退役。

**停止与成本恢复正确含义。** 去掉把累计原文档案 token_cost 当作最终正文大小的门槛；ANSWER 以实际编译窗口判定。成本查询优先选命中、回载、并发都匹配的实测桶。CPU 例中 cold=100 ms/warm=20 ms，旧逻辑都返回100，现在按状态分别返回100/20。

代码：[reading.py](../../controller/reading.py)、[execution.py](../../controller/execution.py)、[claim_graph.py](../../controller/claim_graph.py)、[plan_policy.py](../../controller/plan_policy.py)、[plan_profiles.py](../../controller/plan_profiles.py)。

### 下一阶段机制

B 的目标是选择“下一步能够带来多少最终质量”，而不是累计覆盖越大越好：

`选择计划 = 预计最终质量增益 − λt·新增完整时间 − λg·新增GPU积分 − λh·新增Host积分`。

已付成本进入完整预算；每次动作评价与当前直接 ANSWER 配对。训练样本应包含实际状态、候选动作、执行后的结论变化、最终质量差和成本差。重点覆盖终端关系已找到、重复来源、部分可答、多条件未闭合、全范围枚举与跨文档推理。比较直接回答、一次 READ、一次缺口检索、一次 REDUCE，以及有限两步计划。

下一项实现优先级是 **把最终结论窗口预算前移到 READ/REDUCE**：

- 先计算系统、任务、实际历史和 ANSWER 输出占用，再确定可容纳结论的预算。
- 按 Need 和来源分片分配 READ 输出份额；标记已得到的实体、关系和完整范围。
- 归约为最终结论保留预算，原文摘录使用剩余份额。
- forest 的终止保证与最终窗口可回答性分别计量；较大 forest 的实际候选窗口仍由 B 判断。

当前有限 DAG 已消除重复归约，但还没有完成这一份额分配策略。它直接影响长文的最终可回答率，应先于增加搜索 beam、支持组合阶数或全局重试预算。

已测的无压缩CPU夹具保留100个根时，最终输入为29041个ByteTemplate token，超过该夹具22000窗口。这个结果具体定位了结论表达预算的工作：完整保留事实、条件和来源关系，同时压缩字段重复、标识符与共享结构，再安排最终回答计算。

另一项高收益候选是共享事实读取：当前 \`numeric_need_isolation\` 使计数、求和分别遍历来源，\`build_read_plan(separate_needs=True)\` 为每个 Need 复制完整来源窗口。同一来源、条件、版本下，可用一次原子事实提取建立实体/量值表，再为 count/sum 等 Need 构造各自的运算视图与来源证明。原 Need 隔离模式保留为对照；比较重复原文 token、事实漏提、量值一致性与最终质量。这个改动应接入既有 EvidenceClaim 与 Need 关系，复用同一事实基底，避免再建立平行会话状态。

## C：来源前缀保留

### 当前机制可复用的部分

完整因果前缀、独立 owner、固定输入/DAG 配对、native 对照和 unique 页容量均已具备。`allocate_retention` 对共享因果页只收一次容量；`retention_trace` 同时记录目标下次阅读、受影响请求窗口、回载/重算和占用积分。

### 当前瓶颈

1. **粗化模型失去选择能力。** 当前 scope/TTL 桶的 saved_ms 等于该桶 native−retain 整窗均值。只有两个训练窗口时，同一桶的候选得到同一个常量，覆盖提高不等于价值选择改善。
2. **期限与重访错位。** `capacity_workflow.py` 使用15秒期限，而第二轮在首答后等待30秒；value又仅运行c1，c4/c8均为native。这一批次不能直接评价跨轮C保留与并发收益。
3. **收益尚未对已选集合条件化。** 当前每选一个 owner 会重算剩余候选新增页容量，但预测节省仍为独立 saved_ms。部分重叠 owner 可能同时给同一次未来读取记收益。
4. **零动作原因混在一起。** 容量配置的 GPU/Host 惩罚为0；需要分别统计无预测、当前路径不可保留、完整前缀超过保护容量、收益非正/已覆盖。现有候选与回执字段可直接生成这个分解。

代码：[prefix_retention.py](../../controller/prefix_retention.py)、[prefix_view.py](../../controller/prefix_view.py)、[retention_trace.py](../../profiling/retention_trace.py)、[capacity_workflow.py](../../bench/capacity_workflow.py)。

### 下一阶段机制与实验

先用相同最长观察窗口比较 Native、Lease15、Lease60、Lease180。选择12个开发轨迹窗口，覆盖无重访、native GPU已命中、native Host回载、native重算四类，每类3个；分组依据是原始来源需求及native状态。所有 arm 重放相同请求与外部压力，至少重复一次并交错运行。

以此确认可兑现机会后，学习“期限内来源被再次读取且native不能直接命中”的概率，结合实际回载/重算收益选择不保留、短期限、长期限。访问间隔、来源轮次间隔、当前驻留、压力和并发进入特征；复用现有 paired rows，用共享参数回归或分层统计替代高维精确桶。

收益按未来读取事件计一次，再对已保护集合计算新增可避免成本。unique页容量用于分配保护额度，物理GPU/Host积分用于最终资源评价。冻结C后运行固定B/收益B × native/value，至少同时覆盖c1和c4，使实际节省能够用于追加高收益阅读。

## 评分与冗余清理

本轮统一了三条评价语义：

- MTRAGEval 的 RL_F、RB_llm、RB_alg 全部使用作者条件化规则；raw值保留。受控例：不可答却未识别的raw三分量0.9，正式聚合变为0；正确澄清的0.1变为1。

删除未被调用的 `bench.study_jobs.workload_profiles`，合并重复条件化评分、缺口过滤和召回归属合并逻辑，删除负例装配的 closure=False 分支。首页、架构、课题索引与复现入口按固定模型阅读协议更新，旧 SFT/合并模型配置与失联入口删除。

后续按以下顺序执行，任务之间共享同一实际状态与成本账本：

1. 在既有资产环境离线重评原答案，输出正式完整队列和独立诊断表。
2. 用R0重放执行修正，保持相同输入和预算，列出质量、READ/REDUCE/补检索次数、完整时间和token差。
3. 审计实际可见输入与完整来源，修正阅读协议，训练检索与证据辅助模型并重新采集固定 Qwen 下的 P1 实际奖励。
4. 以当前reader采集动作反事实，完成最终结论预算前移与收益停止。
5. 用固定输入检验C机会、期限和集合边际价值。
6. 冻结A，在同一物理容量和完整时延条件下做B×C；最后一次性评估项目持出集。

完整交付应包括同一cohort的逐题答案、任务状态、证据坐标、有效归约frontier、原生回执、官方分数及完整成本。总体主线是：A提高每次读取的证据价值，B把计算分配给有效阅读并及时停止，C把可兑现的复用收益转为更多可用阅读预算。
