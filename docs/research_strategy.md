# ContextKV 研发策略

2026-10-24。以多轮文档问答的质量、完整响应时间、资源效率和可靠性为共同目标，先交付完整可用流程，再围绕真实瓶颈改进。只使用Qwen3-8B/32B；Qwen2.5-7B已退役，不再使用或开展其相关实验。历史结果保留为复用和纠偏依据，不能变成当前执行清单。

**优先级纠偏：** 场景与职责以[项目范围](project_scope.md)为准。现有基座上的A/B/C完整协同与共同负载联合验收是主线。不能把基座回答中的一般语义错误直接转成训练任务，也不能以新增训练/评测配套代替本系统的实际增益。训练暂缓扩展，已准备的32次生成不执行。

## 当前决策

- **可用主线：** CLI与HTTP query-only入口复用证据身份/完整QA、BM25/Hybrid检索、CorpusIndex原文条件闭包、共同候选、单次回答与原生提交/恢复。固定策略无需成本表即可运行；复杂B/C选项不阻碍系统交付。
- **工程先行：** 保持controller/native/owned共同模型、采样、材料与预算，修复真实接口和异常断点。旧默认/固定实验驱动已移除；本轮补齐HTTP检索、历史/幂等/恢复与计时，修复部分启动加载资源泄漏、trace无界累积及历史序号偏差。具体状态见[模块盘点](implementation_plan.md)和[HTTP入口](http_retrieval.md)。
- **必要才实验：** 先读已有证据和实际实现，再做CPU合同/小诊断。只有剩余不确定性会改变技术选择或支撑重要结论时才使用GPU；不根据已有runner反向决定实验规模。
- **复杂机制须证明净值：** 不为创新而保留分支，不因局部MAE、命中率、合法引用ID或召回率改善就宣布整体有效。没有优势则采用强简单组合，负结果也是可交付结果。
- **按适用场景检验成熟机制：** 先确认复用/适配正确、机制启用及所需负载条件存在。未标定而回退、无缓存竞争或回访的结果不能直接否定B/C；局部负面观测先定位原因，已有正面能力和收益保留。主结论可体现更快、更多服务或同服务更省资源，不要求所有指标同时改善。核心口径见[指标与判断](project_scope.md#核心指标与判断方式)。
- **先消除确定的信息损失：** 已修复显式来源关系在提示渲染时丢失，以及SDK多片段无法进入检索的问题。它们让已具备的材料和关系真正到达模型；不需要新抽取器、额外生成调用或语义保证。对原材料缺少的条件/版本仍保持未知，不通过新规则补造。

## 复用、优化与贡献条件

| 方向 | 保留的基础 | 值得实现的扩展与成立条件 |
|---|---|---|
| A证据与上下文 | 版本化原文、BM25/BGE、RRF、成熟reranker、共享完整候选 | 减少对象/条件/出处错误并保持回答覆盖；来源充分性、选择适用性和最终转述分别诊断，新增成本必须值得 |
| 支持组织与归因生成 | [AFTG](https://aclanthology.org/2024.acl-long.182/)、[ReClaim](https://aclanthology.org/2025.findings-naacl.55/)及[JCA固定实现](https://github.com/jenhsia/joint_constraint_aggregation/tree/3cb4413e4b305893d3206a302eea29954279b66e) | 当前只复用精确地址/要求关联思想。不能把短JSON计划称作专门训练、trie与证据隔离的复现；有具体新机制再实现，不重试已失败提示 |
| B决策与成本 | 原生工作量/预算、阶段分解、lookup/NNLS、完整响应与输出长度 | 候选确有取舍时才标定必要形状；用动作差值和真实闭环评价，不把更准单臂拟合当贡献 |
| C生命周期与资源 | SGLang Radix/HiCache分配、传输、淘汰；CAS/outbox/epoch和共享pin | 业务解除保活与物理释放分开；有自然竞争/回访需求时解释保护和重算代价，不建立影子scheduler |
| 工程集成与评价 | 共同scope/recipe、真实IDs/receipt、HTTP与CLI共享检索/完整历史/恢复、失败分母、质量绑定、B6唯一执行 | 完整可恢复流程、可复算产物和简洁维护是工程成果；算法优胜另由同范围证据建立 |

固定作者机制、许可和移植限制见[支持设计](source_bound_generation_design.md)、[精确支持地址](source_local_support_design.md)。AFTG某些模糊/跨源回绑不照搬；ReClaim训练及adapter/KV重置不在当前Qwen3简单计划中。复用应取其有效原理和正确实现条件，不按论文名称堆功能。

本轮[低额外调用调研](../runs/grounding-low-call-research/README.md)只保留有明确用途的两条路线：SPIRE的结构上下文思想已用于修补显式关系的数据损失；若进一步改变单次生成的支持行为，先离线审查[LongCite](https://aclanthology.org/2025.findings-acl.264/)公开归因监督是否覆盖目标场景的条件、量词、多轮指代及无支持情况，再决定Qwen3适配。作者[固定Apache-2.0代码](https://github.com/THUDM/LongCite/tree/d7d772e39fb15357749f54a2fe1e2dce77df5255)中的首次字符串回绑、越界夹取和删异常不能照搬。低在线调用仍有教师与训练成本；当前未训练、未换权重，不将合法引用监督预设为语义修复。

上述[实际数据审查已完成](source_local_support_design.md#公开归因监督的实际适配检查)：固定12条/6MiB已有真正条件与跨句监督，也出现与目标场景同类的错绑和范围变化；缺多轮/来源身份字段，部分样本超当前上下文。因此当前不直接做LongCite原数据SFT，不扩大下载或训练来验证已明确的数据缺口。接续优先寻找有真实多轮、可追溯支持范围与无支持情形的监督基础，或实现有可验证依据的适配；不是再增加提示规则或把已有审查改名金标。

接续已落地[Doc2Dial离线适配](doc2dial.md)：v1与v0.9显式分开、角色序列和精确多span保留，语料/监督物理分离；实际两份train转换及BM25→Qwen3候选桥接通过。v0.9的OOD是给定文档范围外，不能训练成“整个语料不存在答案”；条件标签也不是逻辑真值。FaithDial可复用修订思路，CHARP的同知识/不同历史消歧设计提示下一机制必须检查历史条件是否真正改变答案，而不只检查引用有效。这些实际字段和负例将用于有边界的机制适配，不因数据量已够就立即训练。

后续[条件推理与对话决策审查](applicability_mechanism.md)进一步区分了来源规则、历史中的用户事实与是否值得澄清。DISCERN/MUDERN的状态监督和ACT的动作反事实可复用其研究原理，但旧实现中的二值极性、首次回答覆盖以及未来目标泄漏不能照搬。先完善严格因果的原始对话样本接口；条件语义尚未建立时不增加布尔规则引擎或在线hard gate，也不让这一条研究路线阻塞B成本采集和服务可靠性的实际修复。

[有源回答训练链](grounded_training.md)作为可选研究产物保留：RAFT证据条件SFT、PA-RAG范围偏好思想、精确目标loss、LoRA及独立checkpoint导出可供以后复用。训练数据与grounding噪声已记录，不能当作语义真值。其潜在价值不等于当前优先级；现在不继续扩训练、teacher或训练专用评价。

新权重的工程接入已实现为离线导出：完成的adapter经PEFT `safe_merge`转为独立BF16 dense checkpoint，发布内容绑定的scope v2后复用现有controller/stock/native入口。v1身份保持不变，新scope区分同尺寸不同权重，拒绝基座KV及成本标定混用。safe_merge只检查有限值，BF16舍入可能改变增量；这项实现不预设语义提升，实际CPU运行结果与后续8B/GPU验证分别记录。无需为动态adapter另建缓存协议，也不以当前选择禁止将来有明确收益的实现路线。

30条弱监督及来源分区已保留，随后一次30-step 8B训练和CPU合并完成，未做模型生成对比，也没有质量结论。下一项回到当前Qwen3系统：收束统一目标负载和入口、补实际成本/生命周期接线与必要标定，再做同基座强简单策略下的质量—完整时延—资源共同验证。不把训练loss下降、合法引用或更多测试文件当作核心目标进展。

## 执行顺序与停止条件

1. **收束完整流程。** HTTP自动检索已复用现有主线，完成集成回归与配置文档后保持可用；实际模型接口若仍有未覆盖边界，只做最小充分验收。检索耗时计入端到端而不重复归入控制成本，缓冲HTTP响应不冒充客户端流式TTFT。研究探索不无限推迟交付。
2. **解决下一瓶颈。** 接线完成不消除来源适用性、对象/条件/引用语义错误；这些是A的主要质量缺口。Qwen3序列化/缓存边界、必要候选成本与模块协同分别按已有证据处理。已有单次基座继续可用，未经支持的机制保持隔离；上传服务、多租户和新检索框架不是当前前置。
3. **验证保留机制。** 明确相同模型/材料/预算/资源，完整计入检索、计划、所有生成、传输和提交。先小规模诊断，再对有潜力的关键结论做必要强基线/消融；及时终止无价值方向。
4. **冻结和交付。** 稳定实现/评价后才开展所需独立测试；不把test改名dev调参，不把助手审查当人审。工程可用、批次完整和优胜成立分开报告。

不自动重跑旧模型、13格跨模型、更多judge、重复小集重排或全部容量组合。不逐请求或反复重哈希权重/语料；新checkpoint只在显式导出发布边界一次读取权重内容建立身份，后续启动检查元数据和库存、不读tensor body。避免隐式重试、未使用抽象和影子cache。边界校验一次，内部复用已验证状态；保留输入身份、幂等、CAS和真实前缀等必要正确性条件。
