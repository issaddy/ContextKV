# ContextKV 研发策略与阶段交付

2026-10-24，全局复核后的当前策略。目标是多轮文档问答下回答质量、完整响应成本、有限 GPU/host 资源和工程可靠性的综合权衡。“更优”须相对同模型、材料、预算和资源的实际强基线成立，不宣称求得一般意义的全局最优。本文替代历史报告里的待办顺序；历史运行、负结果及实现身份保持不变。

**本轮诊断已完成：** [12题真实结果](source_plan_diagnostic_validation.md)保留36个回答位置，实际45次诊断调用加3次接口检查。N全部准备截断，P三次准备截断，完成答案仍有可核的缺源误判/错引。当前v2不扩到159，不按原样产品化；继续单次工程基座。[指定来源支持地址](source_local_support_design.md)已用现有matcher/SpanRef完成薄离线原型；43条已有source坐标可回放，不因此授予语义或下一GPU实验资格。

## 当前判断

**工程底座已贯通，研究上的整体优胜尚未成立。** 版本化证据、完整 QA、双候选、成本模型、原生缓存、提交恢复、数据/评测及矩阵均有实现与真实验证。主要缺口是选出一个值得集成的共同回答机制，并在它上面评价 B/C 净收益；不是继续补全所有实验组合。

## 原理、复用和可能形成的贡献

重点误差链是：所需来源缺失 → 有来源但选择/适用性错误 → 计划正确却在回答中改变条件或出处。三者需要不同措施。引用身份正确只解决出处存在，不推出语义支持；完整正文也不推出条件得到使用。

| 方向 | 复用基础 | 待检验的适配/扩展及贡献条件 |
|---|---|---|
| A：支持选择与回答实现 | BM25/BGE、[AFTG](https://aclanthology.org/2024.acl-long.182/)、[ReClaim 固定代码](https://github.com/pdxthree/ReClaim/tree/bc997dda1340eb6facaf1787294bad3377754914)、[JCA 固定代码](https://github.com/jenhsia/joint_constraint_aggregation/tree/3cb4413e4b305893d3206a302eea29954279b66e) | 关联问题要求、来源适用范围与支持单元，保留原身份/条件和实际 QA。相对共同提示的直接回答和普通准备，减少条件/支持错误且保持回答覆盖，额外成本值得。短计划不等于这些训练/多调用方法的完整复现 |
| B：有边界的在线选择 | 固定 SGLang 原生工作量/预算、阶段成本、查表/NNLS、候选配对与会话留出 | 用可获得的信息比较 APPEND/REBUILD 的完整增量成本；不将容量预留当服务长度、共有控制成本当切换惩罚。只有真实闭环优于强简单规则才成立，不以单臂预测更准替代 |
| C：业务与原生缓存协同 | SGLang Radix/HiCache 的分配/传输/淘汰，SQLite CAS/outbox、epoch 身份 | 提交后解除旧 epoch 业务保活；有竞争时按业务工作集选择备份。区分解除保活与物理释放，验证联合负载的保留收益与重算代价，给出适用区间 |
| 系统工程与评价 | 同源 manifest、真实 IDs/receipt、原始评分绑定、匹配消融、dev/test 隔离 | 共同模型/采样/材料入口、一次业务提交、全链路成本/失败分母、B6 赢家别名。形成可复现工程，但不单独替代算法优胜证据 |

作者实现的假设、许可和移植问题见[方法设计](source_bound_generation_design.md)、[生成与提交边界](source_bound_generation_integration.md)、[联合成本模型](joint_optimization_model.md)。AFTG 的模糊回绑、部分路径的正文截断、ReClaim 固定 tokenizer 假设不能照搬。当前全开发材料仍以整段单元为主，仅 2/159 轮有结构表格，不能声称已实现普遍的细粒度论证图。只有诊断证明需要时才投入精确 highlight/条件表示或受控转述。

允许替换路线，不为保留 A/B/C 名称而保留无效组件。论文贡献由机制与证据形成，不预先指定必须胜出的算法。

## 当前工程切片

1. **消除 B6 重复执行。** 赢家保留唯一 job/产物，`method_aliases: ["B6"]` 与 `method-aliases.json` 提供名称映射；失败和质量绑定沿用原 job，真正 repetitions 仍分别执行。见[B6 合同](b6_joint_sweep.md)。
2. **统一正式原生入口。** B0/B1 使用共享 RunConfig 的显式本地 scope、context、四字段 sampling，核对实际服务。旧 7B 路径兼容；新模型的静态入口已实现，后续显式[owned矩阵](b6_owned_matrix.md)也接通共同scope/recipe及实际资源校验；旧13格自动构造器保持7B/greedy；随后[8B owned B1/Controller四调用验收](owned_local_scope_validation.md)完成，关闭这一功能缺口。见[原生模型入口](native_model_scope.md)。随后B0的新scope/采样入口已完成一次真实合成SSE检查；新B1/联合负载不能由此追认，见[限定结果](source_plan_diagnostic_validation.md)。
3. **减少诊断重算。** `plan_selected` 直接保存已有 Plan 的收益、margin 和稳定期状态，不增加报价、哈希或预测器。纠正共有 control P95 乘二作为切换成本的旧建议，不借此调参数追结果。

本轮机制诊断采用 Qwen3-8B、non-thinking、显式 `.7/.8/20/0`、完整 QA/正文、32768 窗口、final cap1024、Rebuild。这是工作配置，不是质量赢家或最终联合配置。既有 32B 只作能力参考，不自动复制矩阵。新机制未获支持前，核心保留单次生成与原生提交路径。

## 有限阶段与停止条件

### G0：收束问题与交付合同

先完成上述接线、独立审查、低成本回归和运行说明。保留已准备的 159×5、最多 795 次调用 v1 runner作为代码复用原件，**不启动其全量批次**。其 A0 用旧 Q0，两阶段还增加目录和通用指令，未充分控制“提示改善”与“规划收益”。不能由已有 runner 反向决定实验规模。

### G1：先判断额外规划是否值得

当前版本已执行下述12题设计，未通过扩大投入的条件。记录N/P准备未完成与最终错误，不提高预算补跑，也不将缺final的N当成质量差的对照；后续支持表示的修订须是另一个明确机制问题。

三臂使用共同完整材料、目录和逐字相同的最终通用指令：D 直接回答（1024）；N 普通 notes（384）后回答（1024）；P 支持/适用性计划（384）后回答（1024）。D→N 检验额外准备，N→P 检验结构支持组织；P 的 grammar/表示仍是联合变化，不能分别归功。旧 Q0/32B 仅作历史质量参考，不重跑第四臂、不用旧时间作因果对照。extractive 复用同一 P 计划，零新增模型调用。

初始 **12 题、最多 60 次生成**：四域各 3 个不同会话，各域分配早/中/晚轮；只依输入元数据按固定 seed 抽样，不看答案、错误标签、reference、qrels。每轮保留原 8B 实际完整历史和五源。它是已见 dev 的机制诊断，不是无偏质量估计或独立测试。失败、length、空计划、合理拒答和抽取超预算均保留，不因解析失败换题。

全部样本审查来源充分性、计划适用性、final 条件/引用/覆盖与完整成本。来源不足就研究检索；计划错误就改选择/要求表示；计划正确而 final 失真才研究归因生成或转述。D 足够就采用单次方案，N/P 无可辨增量就停止结构复杂化。若信息不足，最多一次预声明扩充到 24 题，扩充顺序在首批输出前冻结；也可保留简单方案，不循环换 seed/提示直到出现胜例。

只有出现可追溯的条件保持增量、覆盖无系统性破坏、额外成本值得进一步检验，才做一次完整 159 开发比较。未支持则保留负结果与可用简单配置，结束此机制版本；不把“必须 P 胜出”设为交付前置。

### G2：获选方案接回业务

只产品化保留的机制。若为两阶段，复用 attempt/outbox 实现“两次调用、一次已发布 QA 提交”，私有计划不入历史；核对失败恢复、下一轮完整 QA、原生 output IDs 与实际发布文本一致，合计两阶段成本。若选 D，不引入通用 workflow 框架。

随后做必要的自有历史 P2 与共同 Cloud P3，P3 用成熟共享检索基座，计时从 arrival 覆盖检索。冻结输入重放不能代替闭环。其余域先保留 P2 泛化，不建四域检索×缓存全矩阵。

### G3：最终 B/C 的净价值

固定共同 A、模型/采样、主容量和主要 write policy。复用已有结果缩小候选，只为该配置采必要成本支持；不借用旧模型/采样 artifact。比较少量等预算强简单组合与必要 B4/B5/Ours，消融围绕实际采用机制。未触发 host 压力的负载不能证明 C 的压力收益，也不为制造收益悄改负载。

主比较/关键结论才做独立系统重复和区间，根据已有波动决定规模，不复制 13 格×容量×模型。归档在计时后，固定或轮换顺序，重复不增加独立会话。Ours 没有净优势就采用强简单组合作稳定配置，如实交付；不无限加预测器、降 margin 或追支持率。

### G4：冻结研究批次并交付

固定代码、方法、artifact、模型/采样、质量协议与所需主对照后才打开 heldout。原方案 Cloud P3 测试主结果不能由 P2/fixture 替代；测试不得事后改名 dev 继续调参。失败、不确定、无加速也是完整结果。没有真实人类盲审时，只报告固定评价器相对结论；现有正式 `quality_noninferiority_established` 不能由助手填表或换 judge 置真。

分别交付工程可用、研究批次完整、质量/性能主张成立三个状态。前两项可在负结果下完成，第三项由证据决定。安装、演示、配置、原始产物、复算入口、来源/许可与限制共同交付，不因持续研究无限推迟集成。

## 不再自动投入

不原样重复同一 Cloud 小集的 reranker/更多历史/enum/表格复制，不为每个无据 SDK 调用补一个符号，不扩 judge 网格追通过，不为单臂 MAE、合法 ID、低 D2H、高覆盖率单独扩大 GPU 实验。新方法必须对应尚未解决且影响选择的问题，先核作者机制和已有证据，再决定是否运行。

边界校验一次，内部复用已验证状态。保留身份、幂等、真实输入绑定、CAS/epoch；不新增全权重哈希、影子 cache/scheduler、重复解析、隐式重试或无消费者抽象。既有正确 CPU 优化保留，不把局部倍数外推端到端收益。

## 最近工程验收后的投入

统一入口的最小真实运行已完成，不因它可运行就自动重开矩阵。下一步复用既有Qwen3-8B 159轮的真实R轨迹、原tokenizer和`build_candidates`，先逐token复现原R，再审计137个真实前状态的一步A/R候选；22首轮单列。量清可行性、与真实前序input+output的raw/page前缀、潜在新增prefill及额外保留材料，决定新scope是否及在哪些输入形状值得采成本。原轨迹用Q0，不冒充后来的D目录提示；不沿假A结果滚动、不造cache quote、不借旧7B成本，也不从token差宣布时间或质量收益。一次完整CPU审计后收束，只有影响技术选择的剩余不确定性才值得GPU投入。
