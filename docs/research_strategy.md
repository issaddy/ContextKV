# ContextKV 研发策略

2026-10-24。以多轮文档问答的质量、完整响应时间、资源效率和可靠性为共同目标，先交付完整可用流程，再围绕真实瓶颈改进。只使用Qwen3-8B/32B；Qwen2.5-7B已退役，不再使用或开展其相关实验。历史结果保留为复用和纠偏依据，不能变成当前执行清单。

## 当前决策

- **可用主线：** 现有证据身份/完整QA、成熟BM25/BGE检索、共同候选、单次回答与原生提交/恢复。固定策略无需成本表即可运行；复杂B/C选项不阻碍系统交付。
- **工程先行：** 保持controller/native/owned共同模型、采样、材料与预算，修复真实接口和异常断点。本轮已去除旧默认/固定实验驱动，修复P3失败落盘和profiling scope接线；具体状态见[模块盘点](implementation_plan.md)。
- **必要才实验：** 先读已有证据和实际实现，再做CPU合同/小诊断。只有剩余不确定性会改变技术选择或支撑重要结论时才使用GPU；不根据已有runner反向决定实验规模。
- **复杂机制须证明净值：** 不为创新而保留分支，不因局部MAE、命中率、合法引用ID或召回率改善就宣布整体有效。没有优势则采用强简单组合，负结果也是可交付结果。

## 复用、优化与贡献条件

| 方向 | 保留的基础 | 值得实现的扩展与成立条件 |
|---|---|---|
| A证据与上下文 | 版本化原文、BM25/BGE、RRF、成熟reranker、共享完整候选 | 减少对象/条件/出处错误并保持回答覆盖；来源充分性、选择适用性和最终转述分别诊断，新增成本必须值得 |
| 支持组织与归因生成 | [AFTG](https://aclanthology.org/2024.acl-long.182/)、[ReClaim](https://aclanthology.org/2025.findings-naacl.55/)及[JCA固定实现](https://github.com/jenhsia/joint_constraint_aggregation/tree/3cb4413e4b305893d3206a302eea29954279b66e) | 当前只复用精确地址/要求关联思想。不能把短JSON计划称作专门训练、trie与证据隔离的复现；有具体新机制再实现，不重试已失败提示 |
| B决策与成本 | 原生工作量/预算、阶段分解、lookup/NNLS、完整响应与输出长度 | 候选确有取舍时才标定必要形状；用动作差值和真实闭环评价，不把更准单臂拟合当贡献 |
| C生命周期与资源 | SGLang Radix/HiCache分配、传输、淘汰；CAS/outbox/epoch和共享pin | 业务解除保活与物理释放分开；有自然竞争/回访需求时解释保护和重算代价，不建立影子scheduler |
| 工程集成与评价 | 共同scope/recipe、真实IDs/receipt、失败分母、质量绑定、B6唯一执行 | 完整可恢复流程、可复算产物和简洁维护是工程成果；算法优胜另由同范围证据建立 |

固定作者机制、许可和移植限制见[支持设计](source_bound_generation_design.md)、[精确支持地址](source_local_support_design.md)。AFTG某些模糊/跨源回绑不照搬；ReClaim训练及adapter/KV重置不在当前Qwen3简单计划中。复用应取其有效原理和正确实现条件，不按论文名称堆功能。

## 执行顺序与停止条件

1. **修完整流程。** 实际代码/依赖审查→解决已复现缺口→最小必要回归→集成可用配置和文档。每轮有可运行成果，研究探索不无限推迟验收。
2. **解决核心问题。** 优先来源适用性、Qwen3序列化/缓存边界、必要候选成本与模块协同。已有单次基座继续可用，未经支持的机制保持隔离。
3. **验证保留机制。** 明确相同模型/材料/预算/资源，完整计入检索、计划、所有生成、传输和提交。先小规模诊断，再对有潜力的关键结论做必要强基线/消融；及时终止无价值方向。
4. **冻结和交付。** 稳定实现/评价后才开展所需独立测试；不把test改名dev调参，不把助手审查当人审。工程可用、批次完整和优胜成立分开报告。

不自动重跑旧模型、13格跨模型、更多judge、重复小集重排或全部容量组合。不新增权重全哈希、逐请求语料哈希、隐式重试、未使用抽象和影子cache。边界校验一次，内部复用已验证状态；保留输入身份、幂等、CAS和真实前缀等必要正确性条件。
