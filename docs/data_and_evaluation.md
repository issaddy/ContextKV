# 统一 benchmark、指标与已有结果

主线采用统一运行入口、场景覆盖和质量/完整成本口径，优先使用公开任务与原始资料。公开数据仍缺少的重要场景可以补建完整benchmark。各任务按自己的协议和指标报告结果，工程回归与系统评测分别汇总。

固定上游版本为`53fef6f5917c7e10c436f697e69a955dbc795d81`。MT-RAG的`RAG.jsonl`包含110会话/842任务，每题给定五段来源。现有会话划分为22 dev/88 test，见`configs/mtrag_split_manifest.json`；数据使用记录与划分一起保留。

官方MT-RAG和MTRAG-UN的`dataset`字段是描述性字符串。离线加载器按已固定的整文件SHA-256，将它们归一为统一的`name/revision`身份；原文件、问题、历史、证据和标签不改写。自定义数据应使用显式身份字典，不能仅复制作者标签就声明固定版本。该处理修复了真实MTRAG-UN入口在生成前把字符串转成字典的错误。

原生对照的P1允许从选定的非首轮开始，或跳到另一个选定轮次，但必须给出该轮之前的完整作者历史，并按轮次递增。P2/P3仍要求从首轮连续执行且历史来自自身成功回答。两种协议不能共用“下一轮必须等于已执行次数加一”的校验。

MTRAG-UN论文描述666个任务/六域，**当前公开reference文件实际为507个任务/四域**：ClapNQ142、Cloud131、FiQA77、Govt157。每个会话发布一个选中任务，历史最多到第11轮；证据0–38段，其中130个任务没有给定证据。Banking/Telco尚未在该固定公开文件中发布。接入保留全部任务及原始材料，已完成507条读取、调度、完整导出和离线标签关联检查；507条答案的生成尚待执行。

## 公共组合与场景扩展

公开任务覆盖真实多轮检索、跨文档切换和长文本质量问题。MT-RAG承担主比较，MultiDoc2Dial扩展服务咨询和跨文档会话；Loong/ChatRAG按各自任务协议补充，各数据集分别报告。

公共问答集通常没有到达时间、会话停顿、共享工作集和版本更新时间；这些是B/C系统评价需要补充的负载信息。可以直接在完整公共会话上声明到达过程、轮间停顿、并发和GPU/Host预算，复用现有runner，而不改问题或参考答案。已有保存结果先复用，只为尚未解决的容量/竞争问题运行必要负载。

自建扩展使用有版本、可追溯的真实资料，覆盖连续追问、纠正、条件切换、多资料比较、话题回访和部分可答。逐轮记录必要回答点、适用条件及支持来源，保留开发/测试会话划分和标注复核。规模由覆盖缺口与结论所需证据决定。

## 协议与比较对象

| 协议 | 模型看到的历史 | 当前材料 | 回答的问题 |
|---|---|---|---|
| P1 | 数据集给定历史 | 官方给定来源，数量随任务 | 标准给定历史/材料下的质量；支持MTRAG-UN选中轮次 |
| P2 | 本方法此前实际生成并提交的QA | MT-RAG原始预检索来源 | 给定资料下的上下文执行和缓存协同 |
| P3 | 本方法此前实际生成并提交的QA | 本方法真实检索 | 完整A/B/C效果，计入解析、检索、选择、生成和提交 |

P2/P3按公开用户问题序列运行，助手历史由各方法生成。P1与P2/P3分别汇总。任务标签、参考答案和qrels用于离线评分。

矩阵的`comparison_scope: system`允许在`method.retriever_config`声明不同检索/意图机制，评价A/B/C整体。默认`execution`共享检索配方；隔离B/C效果时，同时核对各方法保存的实际历史与所选证据。两类比较共用基座模型、资料范围、问题、采样、输出要求和资源口径。

固定配置可直接运行test分区；从开发结果选择配置时，使用对应冻结记录。评价工具、消融和实验规模按研究问题选择。

## 质量、性能与资源指标

- **质量主指标**：复用官方参考答案、来源支持和可答性/歧义处理评价，按官方任务类别及领域报告。官方脚本提供`RL_F`、参考答案相关评分及IDK/underspecified调整项；名称和算法随固定脚本记录。必要时对关键任务作来源复核，不以引用格式、改写句式或模型输出长度替代回答有效性。
- **系统主指标**：完整响应均值/P95、会话累计等待；在预先声明服务期限后报告非截断达标吞吐。当前HTTP完整返回，内部引擎TTFT仅作诊断。
- **资源主指标**：相同资源下的服务能力，以及GPU/Host唯一KV槽位积分/完成轮次。解析/检索设备、模型驻留和实际调用成本计入系统；输入tokens、命中率和追加比例用于解释结果。
- **可靠性**：失败、截断、未完成轮次、提交/恢复一致性单列。缓存计数异常保留为诊断信息，报告在`receipt_work.invalid_counters`列出原值；受影响的Prefill总量、比例或冷启动分类按缺失处理，回答成功状态及延迟保持原值。

官方离线关联入口会保留当前方法的真实输入和答案，再关联`targets`、`answerability`、问题类型与多轮标签。作者时间戳不进入模型输入，也不被误判为历史发生变化：

```bash
python -m bench.official prepare --input SAVED-PREDICTIONS.jsonl \
  --references data/mtrag-un/reference.jsonl --output runs/mtrag-un-labelled.jsonl
python -m bench.report SAVED-RUN.json --output runs/summary.json
```

官方评分复用`bench.official`和固定上游脚本，记录评分模型、版本和历史协议。重要结论结合来源复核与会话统计，缺少评分记录为未评估。

已有SGLang评分服务可使用统一HTTP入口，依赖在独立评价环境安装，评分不加载模型权重：

```bash
.venv-eval/bin/python -m bench.official generation-http \
  --checkout data/mtrag-official --input SAVED-LABELLED.jsonl --output runs/official-scores \
  --endpoint http://127.0.0.1:30002/v1 --model /media/ssd1/qwen3-32b \
  --judge-revision RECORDED-MODEL-REVISION --max-tokens 2048 --no-enable-thinking
```

该入口调用固定官方RB_llm、RAGAS RL_F、IDK和必要时的歧义评分；不另写评分公式。兼容旧式字符串调用，保持声明的greedy采样，使用LangChain SQLiteCache保存完整模型响应，各完成阶段原子落盘。相同输入和judge设置可续跑；不同答案/模型设置使用不同目录。评分代码改动不再强制重新生成主答案。本次隔离环境使用ragas 0.3.3、langchain 0.3.27、langchain-community 0.3.27和langchain-openai 0.3.29；完整依赖、原包装器与运行记录在`runs/public-main/`，未修改服务环境。
