# API证据扩展之后：必要性、调用闭包与合同检查

2026-10-24。三个冻结开发问题的原材料/SDK源码扩展共12次真实生成均完成，新增证据并未消除代码问题：读文档参数修正后出现错误构造参数，定义题引出额外SDK教程，附件题仍有非法JSON注释。完整审查见[生成验证](api_evidence_validation.md)。下列研究用于决定后续扩展，不将其他任务的论文数字转述为本项目收益，也未执行任何生成代码。

| 固定来源 | 原理与复用价值 | 对本项目的适配边界 |
|---|---|---|
| [WAPIIBench的RAG/CD研究，2026-07 v1](https://arxiv.org/html/2607.05936v1)；[代码25a727b](https://github.com/stg-tud/WAPIIBench/tree/25a727b0116e7227525dc4a9f2efc3c4ebb12d76)，Apache-2.0 | 从OpenAPI检索端点材料，并将规范转换成解码约束；论文同时报告提供更多规范会诱发不必要参数 | 其对象是Axios调用补全。可复用“合法接口合同与用户所需操作分开评价”，不能用合法JSON或合法函数名证明回答满足意图。当前Python SDK与解释性QA不宜直接套其整段Axios语法约束 |
| [When LLMs Meet API Documentation，2025 v1](https://arxiv.org/html/2503.15231v1) | 在四个较少见Python库上分析说明、参数和代码用例的作用；用例质量是重要变量 | 给当前失败提出可检验假设：操作签名需配适用版本的最小初始化材料。论文不是Cloudant/Watson实验；不能由其结论认定任意更多用例都有益 |
| [DyCoder / DyRetriever，2026-08 v1](https://arxiv.org/html/2608.01927v1)；[代码4467456](https://github.com/ZJU-CTAG/DyCoder/tree/4467456b554d6497e1dd9a60ae22444ec3059d90) | 从入口按需探索局部依赖，结合相似检索，避免预建整库依赖图 | 可借鉴“小范围、按需调用链”，但作者用LLM判断依赖，不等于静态已证关系。该固定仓库完整50项树未找到LICENSE，当前仅研究机制，不复制代码或下载其工件 |

本次额外核对了WAPIIBench固定`retriever.py`：同端点有多个检索视图，返回端点级材料，再可选重排；其依赖为Chroma/LangChain及Transformers<5，不能直接替换本工程的固定BGE/5.19栈。可以在现有CorpusIndex内适配多视图指向同一原始来源，而无需再建一个向量库。原文保留、适用版本与闭包仍由已有证据合同管理。此处未复制其实现。元数据留在`runs/api-evidence-review/followup-research.json`。

下一步应分离两项实验。第一项研究是否需要操作证据：位置/定义题保留足够的链接与定义来源，明确请求用法的题才增加完整示例，检验是否减少无据扩写；分类必须来自当前问题和真实历史，不能按已知失败task ID路由。第二项在确需代码的输入上，比较“操作签名/schema”与“同版本构造器、认证、服务URL设置的原始来源闭包”。现有`source_spec`及`CorpusIndex.resolve`已经能表达显式依赖，先复用它们，不重建全库调用图；未给出来源的继承方法或跨包初始化保持未知。

两项都保留原材料、完整QA和原失败输出，分别记新增tokens、额外调用、问题响应范围、符号/参数合同、引用和完整时延。静态Python调用核查可提供可重复的错误线索，但动态参数、变量值、服务配置和用户意图不由签名验证解决。完整可执行性需要另外的隔离测试，不能把AST解析或语法约束通过当作API可运行。当前先完成这12次结果审查与全41轮检索比较，再据具体误差安排最小扩展。
