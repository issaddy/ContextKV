# ContextKV 的联合优化问题与算法研究方向

2026-10-24。依据更新后的研究目标，本文将现有 A/B/C 作为可复用实现，而不把它们或初版方案视为研究边界。以下是本项目的问题建模和待检验设计；不是已证明的新算法，也不将理论引用的保证移植到当前实现。

## 1. 优化对象是一段交互及其资源影响

令请求 \(i\) 的到达时刻为 \(a_i\)，完成时刻为 \(c_i=\max(t_{\mathrm{response\ done}},t_{\mathrm{commit}})\)；没有独立提交阶段的原生参照以响应完成为准。在预先声明的有限任务集合、工作负载分布与资源预算下，运行至任务完成，以完整响应时间为主要性能目标：

\[
\min_\pi\;\mathbb E_\pi\!\left[\sum_i w_i(c_i-a_i)\right].
\]

第一版比较使用相同 \(w_i=1\)，同时报告会话均值、尾延迟、SLO、失败和截断，不通过临时改变权重制造赢家。上式针对完成同一任务集的比较；失败、超时和未完成请求必须单列，不能只对成功者求均值后声称更优。回答质量以各维度相对参照的允许差异约束单独评价，不把“正确性分数+毫秒+字节”随意加权成一个总分。容量受控实验固定实际 GPU/host 预算；资源效率另报告唯一物理占用、完成 DMA、重算和控制开销。质量、时间与资源的冲突用可复核的取舍描述，不能以命中率或少传输替代最终收益。

工作负载也须区分：固定到达时刻的开放负载可以比较相同外部需求下的干扰；当前多轮闭环则在上一轮完成后发起下一轮，动作会改变后续到达时刻和生成历史。后者仍可比较同一用户脚本下的完整交互，但不能宣称两臂经历相同排队状态。两类结果分别报告，不以闭环的更低提交速率冒充更强服务能力。

决策可以包括检索、证据选择与排序、历史表示、追加/重建、写入/保留/恢复以及请求调度。归档原文、实际模型输入、物理 KV 状态是三种不同对象。未来若研究摘要、近似 KV 或其他表示，应预先声明新的保真和质量合同并与完整材料对照；不能改写旧实验的 full-QA/原文保留结论。

状态至少区分：已发生的实际会话、当前已到达 query、候选材料与真实渲染前缀、GPU/host 唯一页及共享关系、ready/pending 状态、活动与等待请求、原生容量预留、业务/epoch 生命周期。未来用户问题、真实剩余输出长度、数据集剩余轮数均不是可直接使用的在线信息。有限 snapshot 不自动具有 Markov 性；必要时使用历史或可验证的条件统计，不以一个业务计数代替完整环境状态。

可行性要求满足实际内存和并发约束、证据身份与版本合同、结果提交和退役顺序。共享前缀只计一次物理占用；已经分配但尚未 ACK 的传输页仍占资源，却不能被当作 ready 命中。retire ACK 改变保护状态，不直接产生同量可用容量。

## 2. 现有方案的根本缺口

`CostModel.predict_native` 已估计当前候选的控制、等待、联合 prefill/host 恢复和 decode 成本；`choose_plan` 比较当前差值，再施加误差门槛与稳定期。这是有测量依据的**逐轮决策**，但不包含新布局对后续交互的状态价值，也未优化对其他已到达请求的总等待影响。现有 `paired_error` 的残差/误差和是工程风险信号，不是候选选择后的统计置信保证。

`conditioned` host 准入比较逻辑工作集、占用和近期淘汰，再施加每请求累计页额度。它已经正确接入真实 BackupKV 路径，但没有显式比较“写入当前路径的收益”与“替换另一条路径的损失”，也没有决定保留多久。其 60 秒窗口、95% 占用和 8192-token 额度是已记录的适配参数，不能作为理论贡献本身。

[完整13格实测](b6_joint_validation.md)提供了三个可用诊断：Fixed4096 每格只有1次APPEND，当前参数接近始终重建；Redundancy40 每格11次APPEND，其行为确实不同，但少prefill未必带来更短完整响应；9个控制器格的host峰值为容量的3.51%–56.81%，没有观察到host满池竞争。这要求分别补强简单基线、检验成本差预测和构造真实竞争，不能通过继续增加门槛解释所有现象。

## 3. 将当前代价与状态变化分开建模

在覆盖所有到达与完成的时间区间，令 \(N_w(t)=\sum_{i:a_i\le t<c_i}w_i\)，则总 flow-time 等于 \(\int N_w(t)\,dt\)。因此，若历史/状态能支持相应条件分布，在决策事件 \(t\) 与下一事件 \(t'\) 之间应使用：

\[
Q(s,a)=\mathbb E\!\left[\int_t^{t'}N_w(u)\,du+V(s')\mid s,a\right].
\]

这里 \(V\) 只计 \(t'\) 之后的剩余成本，不重复计入已经累计的等待。事件时间及转移可以依赖动作，这是一个建模形式而非已求解的优化器。当前候选自身的完整响应预测不能直接充当这个多请求阶段成本；否则容易漏掉并发请求，或与 \(V\) 重复计时。LLM 输出会改变自身历史、后续检索与输入长度，异步传输和淘汰又改变其他请求的可用资源；因此 \(s'\) 必须来自实际动作转移。可以先诊断仅含**已经到达的请求**的残余完成时间，不必先预测未来用户意图或建立大型强化学习系统。该截断问题不等于全部未来交互的最优解。固定后续策略时使用其剩余值；若研究最优值则需要进一步对合法动作取最小。有限任务集全部完成后剩余值为零；有限观测窗提前结束时不能如此处理。

一个纯数学反例说明逐轮最优不足以推出交互最优：假设追加当前花1单位，重建花3单位；随后两轮追加状态各花5单位，重建状态各花2单位，则当前贪心选追加，而总成本分别为11和7。这个例子只证明可能存在未来价值，**不是 ContextKV 的测量结果，也不能证明复杂规划器值得实现**。下一步要用真实分支实验判断这种差异是否存在、是否大于新增控制和预测误差。

时间分解必须尊重关键路径。H2D、GPU计算、流式输出、提交可能重叠；已有联合测量或 first-token 样本不能再加一次同一段传输/等待。资源状态变化也不能凭逻辑 token 长度代替原生分配、ACK与淘汰。

对一条可合法备份的前缀路径 \(p\)，先固定同一初始状态、外部请求/已知延迟、后续策略及观察终点，定义两分支总 flow-time 为 \(J_{\mathrm{skip}}\)、\(J_{\mathrm{admit}}\)。可检验的净价值是：

\[
U(p,\tau)=\mathbb E[J_{\mathrm{skip}}-J_{\mathrm{admit}}\mid s,p,\tau].
\]

\(\tau\) 是拟议保留期限；两分支需观察相同请求集至完成，或显式记录有限观察窗结束后的残余成本，不能截掉被推迟的请求。后续可用避免重算的关键路径收益、写入引起的增量完成延迟、替换损失近似这个差值，但不能直接相加 DMA 持续时间与已经包含该传输的请求等待。两臂原本都GPU命中的访问也不产生host副本收益。这个定义描述研究目标，不是已经具备在线可估计的反事实。

即使host未满，备份也可能因未来不复用而没有净收益；容量紧张时，替换损失尤其重要。若使用容量的对偶价格，价格必须对应明确的资源约束和单位，并检验其估计依据，不能另添一个任意系数。实际计量对象是新增唯一页与合法祖先链；前缀共享、部分恢复和非线性kernel时间意味着不能未经验证便假设收益可加、单调或凹。

## 4. 成熟理论可以复用什么

**成本加权缓存。** Landlord 给对象与取回代价相关的credit，容量竞争时按大小消耗credit，淘汰credit耗尽者；其原始保证针对固定文件大小/成本的在线文件缓存。[作者论文](https://www.cs.ucr.edu/~neal/publication/Young02Online.pdf)可作为区分大小与代价的理论起点。我们有共享前缀、异步双层状态及随批次变化的成本，不能继承其竞争比。最初可在不共享、成本固定的状态回放中检验原算法，再逐项加入真实约束，明确哪些结论失效。

**有容量增长的在线调度。** [Jaillet等的2025论文](https://arxiv.org/html/2502.07115v1)将decode期间内存增长纳入延迟目标，但其理论假设到达时可准确预测输出长度；还采用等长较小prompt chunk、相对容量趋小的prompt、离散batch服务等模型假设；§7使用Vidur数值模拟，§8明确讨论预测误差限制。可以复用容量沿处理进度变化、离线下界与在线策略分开的建模方式，不能把我们的均值长度先验当作完美预测，也不能引用其模拟收益作为本项目硬件结果。现有 native_budget 将原生容量预留与经验服务时长分开，正是需要保留的区别。

较新的树结构淘汰、经验返回时间TTL、工作流驱动恢复应作为互补候选；[RLT、Continuum、KVFlow 核查](cache_reuse_research.md)列出固定源码、实际实现缺口、许可和最小对照。每项复用都要核对作者代码是否真正包含论文算法，以及信息假设是否适用于未知用户下一轮。具有已知工作流的方法不能读取MTRAG未来问题；当前query已经确定的真实前缀需求则可以成为合法的协同信号。

## 5. 下一轮应回答的可证伪问题

[369轮计时分解](b6_timing_diagnosis.md)已经完成，全部按 `attempt_id` 与实际receipt绑定。`server_ttft − forward_to_first_token` 平均占TTFT的93.59%，但只表示scheduler收到至首次forward，包含缓存准备，不能称为纯排队；decode占server elapsed的64.42%。相同输入/输出子集仍未控制到达与驻留，不能由此单独归因写策略或DMA收益。

随后启用只读原生准入诊断，完成[两peer与A/R候选的受控实验](peer_interference_validation.md)：72个episode、264次模型调用，包含27个正式配对。peer完成时间差非零，但27/27自身与总flow-time排序相同，没有证据支持立刻新增外部性评分。大APPEND的GPU-ready与host-only首gate均缺1999 tokens；GPU命中实际保留，锁内/解锁后预算差支持新增pin占用的解释。复用减少计算量，却未消除最终KV容量约束。

该实验的quote在peer到达前取得，不能据它证明现有等待模型已经预测准入时状态；尚未运行cost artifact选择或测planner regret。当前 `min(device_hit, evictable)` 对新增pin量只是一般静态上界，已审计的9次拒绝中恰好等于实际增量。下一步先检验共享已锁前缀下是否造成错误等待分类，再决定是否沿现有只读遍历补充精确观测；不为尚未发生的误差增加全树追踪。上述固定512输出的机制实验也不代替自然EOS、质量与完整闭环验证。

简单阈值、周期和原生能力用于建立真正有竞争力的参照；其搜索预算必须公开，但调参本身不是贡献。对机制的新增要求是：指出现模型缺少的变量或错误假设，给出明确信息边界与算法，再证明真实场景收益足以覆盖开销。无收益或假设失败时，可以简化、替换或放弃该机制，而不是继续叠加规则。

这条路线不依赖某个固定模块必须成为论文主贡献。当前13格、成本标定、检索/证据干预及生命周期实验是不同范围的证据；后续统一实验仍需强基线、重复、质量与heldout验证。现有自动评价器已出现来源错绑漏判，不能因格式完整或相对分数通过，就把质量约束当作已被可靠证明。
