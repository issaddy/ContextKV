## 两个实际建议

### Q1：替换不能完整保留复合句的证据

任务 `c6c3b02ca32795af64c903dd76700517<::>3`，claim 11，offset `[1646,1763)`。回答末句同时断言：Vulnerability Advisor 检查受支持 OS 的易受攻击软件包，并提供安全状态报告。建议将 `E_2b52385ff6` 全量换为 `E_38ea6e4c20`，模型概率从 .0420 到 .9583。

- 旧来源 `ibmcld_01533-4-2366` 明确描述检查镜像安全状态，并生成含修复建议与最佳实践的 security status report；因此它对句子的报告部分有实质支持。
- 新来源 `ibmcld_01533-6329-8623` 明确描述检查受支持 OS 镜像中的 vulnerable packages、相关公告和扫描触发方式；它支持包检查部分。但其正文没有完整说明该句所说的 security status report 功能，不能据单个 .9583 概率断言它单独支持整句。

**审查判断：不接受原样替换为“成功纠错”。** 这更像需要联合两段来源的复合断言。可以保留旧引用并提出追加新引用的建议，或先按两个原子事实分别绑定；不能删除旧来源后把模型分数上升当作证据覆盖改善。这也说明“所有旧引用概率都低”不等于旧引用对每个子断言都毫无支持。

### Q2：最后一句的替代来源正确，但段落绑定仍有歧义

任务 `c6c3b02ca32795af64c903dd76700517<::>2`，claim 3，offset `[283,431)`。末句关于评估镜像安全状态、生成含修复建议和最佳实践的报告。新 `E_2b52385ff6` 对这些内容有直接正文支持，旧两引用概率最高 .0282，新来源 .9414。

**对最后一句单独判断，新引用合理。** 但原答案是四句连续一段，两个旧引用位于整段末尾。旧 `E_5d254fb408/E_6b1b366cdb` 正文明确包含不扫描加密镜像、检查受支持 OS 软件包等内容，恰好支持该段前面的断言。当前按句切分把段尾两个引用全部分配给最后一句，再统一替换，会使前句所需来源从段落中消失。

此外，当前替换输出为两个相同的 `[E_2b52385ff6]`。这来自 `bench/citation_repair.py` 中逐个正则命中都换成同一最佳 reference，缺少集合去重；不是新增两份独立证据。

**审查判断：新来源可作为最后一句的建议补充，但不能确认当前整段替换安全。** 保留旧引用并在最后一句绑定新引用，比删除整段原有来源更符合已读证据；若要自动替换，先解决段落引用作用域。该建议仍需要复核，不能统计为已完成质量提升。

## 最小改进边界

保持该工具作为离线候选建议输出，优先修正两个已由真实案例暴露的问题：联合证据的复合断言不能只按单来源最高概率替换；段尾引用不能未经确认按最后一句独占处理。格式上对建议引用去重。额外增加静态 reject/hash 检查不会解决这些语义问题。

现有偏移校验、缺正文/模型截断不参与替换、inline code 不自动修改、保留原答案等边界有实际价值。下一步可复用原子 claim 拆分或联合证据核查，并保留 before/after 与所有旧/新来源供审核；以真实的这两个失败/歧义案例做回归。不要把同一 MiniCheck 的修复选择分数再次当作独立验收，也不应仅因本次建议不可靠就停止开源方法的适配。当前两份 repaired 文件均只应视为未验证 proposal，默认在线回答保持原输出。
