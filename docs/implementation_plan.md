# 完整工程目标与验收

当前目标：完成完整项目工程，并主动复用、优化和扩展相关开源方法，让证据组织 A、候选决策 B、生命周期 C 在目标场景形成可验证的整体效果。技术方案是起点；候选长度、条件误差、收益校准、混合检索、引用增补和有限容量实验已经形成可运行产物。新的限额关系、来源污染和联合成本问题继续驱动改进，而不是作为结束实现的理由。项目部署在 `/home/relay/songjiayun/ContextKV`，已有 Linux/NVIDIA H200 环境；工程集成、训练探索与真实 GPU 验证连续推进，以明确的资源预算解释效果。

已观察 dev 可以用于特征开发、训练与按会话 OOF。相同会话的两候选、状态重复和提示词变体保持同组；OOF 结果用于开发决策并如实标记，独立 test 不参与选特征、调阈值或挑路线。新增会话有助于提高可信度，但不设置“凑足固定数量新会话才能实现”的前置门槛。

16K 独立标定和六方法联合运行已完成 246 轮，见[联合验证](controller_capacity_validation.md)。它定位了空闲 slot 不足导致集中回退，以及 first-token 表混合前置等待两个问题。`bc6c803` 已实现[阶段拆分](stage_cost_model.md)、原生只读工作量摘要和[条件剩余工作等待估计](admission_wait_model.md)，并完成四方法两重复 328 轮，详见[阶段闭环验证](stage_workload_validation.md)。双候选可比较 52/72 轮，但完成时间仍慢于严格模式和固定规则；等待尾部、状态漂移及稳定轮门槛成为明确改进目标。新增解码计算缓存已在 Linux 的 72 个候选上验证逐字段一致、计算墙时约降低 74%，未混入此前闭环数字；[同一优化后代码的 gate2/gate0 对照](stage_gate_validation.md)又完成 328 轮。gate0 两重复等会话均值比 gate2 下降 19.88%，但仍比 Fixed4096 慢 15.16%；P2 历史/答案已分叉，不把差值当作单个动作的因果收益。当前完整回归 622 项与 6 项子测试通过，随后显式 tokenizer 专项 5 项通过（包含初次跳过的 4 项），Ruff 和安装包源码/许可核对通过。

质量侧的[表格字面关系注释](table_relations.md)完成 82 轮闭环及 8 次冻结历史对照：旧错误 fixture 的对象错绑在 on 中两次消除，但引用缺失和额外不受支持内容仍存在，不能据此宣布整体质量通过。进一步复用 CRAFT 行文本并扩展焦点行与行内来源，已在 12 次冻结历史三臂对照中获得目标缺陷的局部改善，并以 `focus_refs` 接入共享工程路径，见[验证](table_focus_validation.md)。[跨家族开源 judge 与元评测](open_judge_plan.md)也已实现并真实运行；[首轮结果](open_judge_validation.md)表明格式适配与对象/条件语义核查均需改进，继续沿用[答案绑定与盲审链路](quality_acceptance.md)。

## 持续审查

每个工作包完成后检查：代码主路径是否实际调用新增能力；测试是否覆盖业务边界；统计是否区分观察、估计和模拟；基线是否承担公平的开销；跨模块合同是否一致。发现问题直接修复，再运行受影响检查；最终执行完整回归与离线端到端流程。

实现遵循边界校验一次、内部信任已提交不可变状态。内容身份、请求幂等、真实输入关联与 CAS/epoch 约束保留；不新增重复哈希、无依据的保护层、未启用的抽象或隐式回退。
