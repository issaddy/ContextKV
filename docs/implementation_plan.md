## 收尾时的默认配置

- Qwen3-8B生成；Qwen3-32B解释服务采用已验证接线的原生NGRAM。部署实例为生成GPU0、解释/BGE共享GPU1，各自资源必须计入说明。
- `conversational-intent-v15`、`single`检索融合、`ranked`选材、`stable_key`布局；成本配置为`configs/qwen3_8b_cost.yaml`，适用对应H200/16K GPU/54272 Host槽位条件。
- 原文为默认阅读表示。作者列表元数据保留，`source_list_reading: true`显式启用标记；来源窗口、语义选材、表格关系及Host准入按需使用，不全局叠加。
- 32B不套用8B成本表；已退役模型不再用于实验。训练工具仅保留可复用接口。

## 已有实测结论

| 完整系统对照 | 原生 / ContextKV 的RB_llm | 原生 / ContextKV 的完整响应均值 | 结论 |
|---|---:|---:|---|
| MT-RAG Cloud：21会话、164轮/方法，版本`d70084e` | 0.7037 / 0.7409 | 1.654 / 3.978秒 | 该队列质量评分有正向收益，代价是更长响应；差值95%会话区间[+0.0049,+0.0735] |
| MultiDoc2Dial：24会话、161轮/方法，版本`44f2158` | 0.8056 / 0.7925 | 1.333 / 1.916秒 | 质量差值区间跨零，未建立整体优势 |

Cloud另有原生＋A对照，RB_llm为0.7250、完整响应3.780秒；相对同A的原生执行，当前未证明B/C带来净速度收益。上述均为固定公开子队列及同族自动评分；来源支持评分的缺失与范围在评价文档中保留。主比较并发为1、没有Host恢复，不能据此宣称资源竞争下的优势，也不能将旧版本数字直接视为最新版本结果。

机制层的取舍已收敛：

- **联合任务/选材**：保留一次调用的实现，替代旧两阶段可选流程；8个开发会话中覆盖改善但质量相近、平均响应增加，默认仍用排名选材。
- **作者列表标记**：56题固定输入对照的原文/标记RB_llm为0.8080/0.7839，差值区间跨零且输入、输出增加。保留结构数据和显式能力，撤回自动标记，不继续格式搜索或个例补丁。
- **状态依据v15**：381条保存请求中，73条补回81处变化上下文；近期原话与最新状态全部保留，平均解释输入1659→1628 tokens，没有新增超预算。该结果是输入检查，不是新的回答质量或系统提速结论。
- **控制与生命周期**：重复容器遍历、历史来源遍历、重复校验及冗余日志已精简；2万次原生追踪器关闭检查验证了退役元数据有界化。GPU物理收益仍按实际负载独立判断。
