# 完整工程目标与当前执行计划

2026-10-24 更新。目标是可运行、可维护、可复现的 ContextKV，让证据组织 A、在线决策 B 与生命周期 C 取得实际综合效果。技术方案是起点，允许组合、优化或替换；工程完成不要求所有研究分支有效。

**优先级以[研发策略](research_strategy.md)为准。** 本文保持当前执行计划，不再累积流水。历史数量、源码和正反结果见[验证记录](verification.md)及各 validation 报告，不追认为新版本证据。

## 有限后续阶段

1. **机制取舍：** 定位来源→计划→实现的错误通道，单次方案足够就采用它。仅有明确增量才做一次完整开发对照；负结果可以结束当前版本，不循环调提示。
2. **业务集成：** 只接获选 A；两阶段若保留，复用恢复/提交，实现一次业务提交、实际发布 QA 与完整成本，再做自有历史 P2/共同 Cloud P3。
3. **B/C 联合：** 固定 A、模型/采样与资源，仅采所需标定，比较有限强简单组合和必要消融。复杂策略须证明净值；未触发的组件不扩格子。
4. **冻结交付：** 方法与评价冻结后做预声明 heldout 主比较，保留失败/不确定；交付安装、配置、运行、来源/许可、原始产物和复算入口。工程可用、批次完整、优胜成立分别报告。

停止条件、复用依据与统计边界见[研发策略](research_strategy.md)。不把全部模型×容量×并发×写策略×提示作为验收要求；旧报告未执行项不自动进入当前清单。

## 工作包合同

| 工作包 | 持续保持 |
|---|---|
| A | 完整正文/QA、稳定 ref、版本/条件闭包、实际 token 前缀；语义效果与身份正确分开 |
| B | 实际模型/采样/资源绑定，支持域/回退明确；评估动作差值与完整成本，固定规则无无用报价 |
| C/E | 提交后幂等退休、失败不提交半答案、共享前缀不误删；原生传输/淘汰负责物理回收 |
| D/Q | 协议隔离、无 reference/未来泄漏、评分绑定实际输入/答案；助手审查不代替人审 |
| X/R | 同源基线、真实重复、有限等预算选择与 test 冻结；固定上游/许可，区分直接复用、思想适配、新增机制 |

验证规模由变更风险与关键不确定性决定。边界校验一次，内部信任已提交不可变状态；不加重复哈希、无收益保护层或隐式重试。先分析原理，必要时才实验，由结果决定保留、优化或替换。
