# 完整工程目标与验收

当前目标：完成完整项目工程，并主动复用、优化和扩展相关开源方法，让证据组织 A、候选决策 B、生命周期 C 在目标场景形成可验证的整体效果。技术方案是起点；实测暴露的输出长度、误差估计与引用支持缺口已进入下一轮开发，而不是作为结束实现的理由。项目部署在 `/home/relay/songjiayun/ContextKV`，已有 Linux/NVIDIA H200 环境；工程集成、训练探索与真实 GPU 验证可连续推进，主实验先保持单卡和明确的资源预算。

已观察 dev 可以用于特征开发、训练与按会话 OOF。相同会话的两候选、状态重复和提示词变体保持同组；OOF 结果用于开发决策并如实标记，独立 test 不参与选特征、调阈值或挑路线。新增会话有助于提高可信度，但不设置“凑足固定数量新会话才能实现”的前置门槛。

| 优先路线 | 直接复用与改进 | 首个可交付结果 |

| 证据支持与质量 | 复用开源本地 grounding classifier，按稳定 ID 对完整可见原文做支持重评分，针对错绑/资料不足开展有限纠偏 | [方案](evidence_support_proposal.md)、可复核支持矩阵、误报与修正前后完整成本/质量对照 |

保持同材料的缓存消融与允许检索/质量过程变化的增强实验分别组织。比较条件用于解释效果来源，不用于禁止探索；新路径形成可运行结果后再据其质量、开销和适用区域决定主线组合。

## 持续审查

每个工作包完成后检查：代码主路径是否实际调用新增能力；测试是否覆盖业务边界；统计是否区分观察、估计和模拟；基线是否承担公平的开销；跨模块合同是否一致。发现问题直接修复，再运行受影响检查；最终执行完整回归与离线端到端流程。

实现遵循边界校验一次、内部信任已提交不可变状态。内容身份、请求幂等、真实输入关联与 CAS/epoch 约束保留；不新增重复哈希、无依据的保护层、未启用的抽象或隐式回退。

## GPU 验收

真实 CUDA 启动、多进程通信、模型生成、容量压力、传输/计时准确性以及性能和质量结论，必须在目标 GPU 环境验证。先完成固定模型与引擎的真实集成，再验证冷/GPU/host 标定、开发集调参与冻结测试；运行记录保留实际配置和失败，不将冒烟当作完整质量或性能实证。host 写入准入、第二模型、多步预测等增强按实测瓶颈决定，不在首版中预设收益。
