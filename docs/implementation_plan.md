# 当前实现与交付状态

2026-10-27。目标是多资料、长上下文、多轮问答的质量优先 A/B/C 协同：先提高任务理解、条件承接、证据适用性与回答完整性，再改善完整响应性能和资源效率。应用不限定行业；场景见[项目范围](project_scope.md)，分版本结果集中在[数据与评价](data_and_evaluation.md)。本文件是唯一的当前工作清单。

## 当前可用工程

| 模块 | 已实现及协同 | 当前重点 |
|---|---|---|
| A：任务、证据与上下文 | 从首轮初始化任务、条件和复合子需求；增量更新、纠正与回访；子需求联合召回及原池重排；原始文档阅读视图；版本/依赖闭包；完整实际QA；共同A/R证据与引用范围；精确正文共享、简洁来源导航 | 当前条件与资料中流程/版本的匹配仍是主要质量瓶颈；实际阅读单元需要参与选材，不能用小片段排名代替适用性 |
| B：执行成本选择 | 同批原生报价、实测forward/decode、回答长度估计、分动作控制开销反馈；原生准入预算与服务长度分账 | 已有8B成本表适用于对应H200配置；更长输入的prefix/suffix/setup测点仍有缺口，优先复用保存报价定位必要补充 |
| C：生命周期 | epoch软引用、CAS、attempt/outbox、成功提交后退役、响应丢失恢复与引擎重启处理 | 继续复用SGLang原生分配、锁、传输与淘汰；退役ACK表示引用解除，不冒充物理内存立即释放 |
| 服务与交付 | CLI/HTTP自动检索、多会话、幂等、实际历史/原文审计、关闭恢复；固定SGLang与Qwen3部署；wheel/sdist、同源原生/简单对照 | 8B生成GPU0、32B解释/BGE检索GPU1，完整耗时与两服务驻留统一核算 |

共同链路：当前任务及子需求 → 检索与选材 → 同一证据集合的APPEND/REBUILD → 原生报价与成本选择 → 生成 → 回答/意图/epoch原子提交 → 旧引用退役。幂等重放和恢复使用已固定计划，不重复解析或检索。

可选的来源ID选择复用同一32B解释客户端，在完整候选原文中选至多五段；默认仍为排名选择。来源窗口、表格关系等能力按实际用途显式使用。32B解释实例不套用8B成本表，正常服务无需训练。

## 当前机制进展

- 首轮开始保留复合请求的各项需求；条件改变作用于所有子查询。已有编码器批量编码，复用BM25/BGE/RRF与重排器；相邻原文先评分再竞争预算，不无条件扩大生成上下文。
- 来源选择只输出原始文档ID。真实诊断发现细粒度行号/用途标签不可靠，已删除该扩展和对应状态/请求哈希处理；来源导航也不再使用词匹配摘录。
- 模型输入移除重复的内部身份与provenance字段，完整信息仍保存在账本。既有消息与缓存前缀不改写，原始证据与实际历史保持完整。
- 解析和来源选择HTTP在BGE锁外执行；token计数与共享客户端复用已有短锁，避免串行等待和重复模型加载。
- 原始文档阅读器按完整片段匹配固定版本原文，仅允许定位时的空白差异，补齐自然段并合并重叠窗口。实际阅读视图替代匹配切片，原始排名单独保存；生成与检索评价各用对应材料。同一窗口保留稳定派生身份、参数锚点并复用已有A/B/C链路。

本轮全量本地1688 passed、16 skipped、8 subtests；阅读器集成版本Linux相关153 passed，最终参数锚点及复用修改后的Linux针对性检查60 passed（含实际Qwen3分词）。公开MTRAG-UN的507个任务已通过读取/调度/导出/标签关联及实际分词检查，尚未生成整套答案。原文恢复在205个Cloud公开任务涉及的702个不同原片段上完成对齐检查：663个恢复上下文、39个已完整。

固定选择两个公开dev会话的第2–4轮，共6题，以原片段和原文窗口各生成一次。12次回答均完成且无截断，提交、幂等重放和关闭完成。窗口版改善了Query API用途分类，但参数位置及customer/customization ID混用仍存在，总输入增加34%。因此保留可复用能力并继续显式启用，不默认扩展所有上下文；本次P1诊断不替代多轮P3整体质量和性能评价。原始输入、输出及来源审查统一在`runs/source-context-mechanism/`。

## 本轮审查与清理

公开主benchmark采用MT-RAG，MTRAG-UN补充选定轮次挑战；现有Cloud P3与四域P1分别有可运行配置。完整系统比较允许方法使用不同检索配方，执行机制对照保留共享配方。固定方法不再被强制先做开发调参。证据读取和导出不再限制为五段/十段，真实预算仍按完整输入计算。

来源选择器可以直接消费dense/hybrid候选，取消强制重复重排。删除无运行依赖的离线概率补引用原型、不可达的重复planner检查、文件摘要之后的重复固定计数检查，以及恒为false的笼统性能资格字段。评价文档合并历史叙述，原件和Git版本保留；CAS、版本身份、原文与恢复边界，以及有复用价值的数据/评分/导出接口继续保留。

## 下一步与边界

优先让任务理解、选材与实际阅读单元协同：对小片段评分后再扩展原文，会引入尚未评估适用性的内容；仅增加文本不能解决条件和接口混接。复用现有解释器、候选评分和原文关系，减少重复控制调用，不继续围绕这六题调窗口或提示。实现后用公开任务验证能影响方案决策的问题，自构案例限于缺陷复现；随后对有希望的整合版本开展必要的质量与完整成本对照。

工程闭环已经可运行，质量提升目标继续推进。独立跨领域优势、复杂条件下的稳定适用性，以及更长输入下的成本支持仍需完善；不把全部基座错误或庞大实验矩阵作为阶段交付前置。
