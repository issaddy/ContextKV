## 本次完成的关键修正

- 派生意图同时进入检索、重排、证据组织和生成，再随回答原子提交；重放/恢复不重复解析，原 QA 与证据正文不被改写。
- 普通轮次复用原 last3 检索，明确依赖才调用 Qwen3；近期解析传递已继承条件，明确回访可访问全部用户历史。版本前缀与多先行词回访不会选错归档来源。
- 当前检索优先级与缓存正文顺序分离；解析 HTTP 等待与 BGE 模型锁分离，保持原模型单次加载与串行 forward。
- 原生 JSON 编码器直接遍历 token 容器，消除写状态/事件时的重复 Python 深遍历；固定 prefill/setup 插值结构在启动时复用。
- 不再把旧回答协议的 580/1024 长度分布套到当前服务；复用原耗时测量，用配置先验、已完成历史和当前服务完成长度估计后续成本。追加/重建的控制成本分别统计，无训练或额外生成。
- 本轮允许 ID 进入 SGLang 原生 regex 解码约束，原生对照同样启用；保留原模型输出，不事后换引用。已移除证据不相交就禁止追加的启发式限制，按实际 token 前缀、预算与执行成本比较两种候选。
- 增加共用的原文来源定位与部分回答规则；真实验证表明它们不能替代语义支持检查，相关失败保留。

本轮新增字面任务承接，省去明确具名补充指令的一次模型调用；来源资格采用轻量名称投影，保留原来的资格判断而不构造随后丢弃的诊断目录。外部解析仍验证所需字段和历史身份，额外说明字段不再使有效解释失败。证据版本、资源预算、幂等提交与恢复检查保留。

额外解析模型已改为可选；无模型配置也能在同一检索/生成/提交链使用任务承接与历史查询。ContextPilot 的缓存布局和当前检索优先级已接通，重复优先级注释被删除，过时版本不会进入优先级列表。报告将未评分与不合格分开，移除恒为 false 的笼统性能标记。

## 剩余瓶颈与投入原则

1. **目标任务的承接与证据适用性。** 优先修复影响实际任务的对象/条件混淆、任务遗漏和无依据步骤；来源支持与引用格式分开评价，不把统一行内引用样式当作所有场景的门槛。
2. **相对原生的净收益。** 两个真实检索会话已观测到响应收益，Host 单位占用略高。短回答控制开销、首次检索初始化和生成长度会影响整体结果；不把 CPU 回放、局部命中或本批吞吐当作普遍性能/容量结论。
3. **结果范围。** 当前对照是开发诊断，不是独立冻结测试。正式论文级整体优胜需要明确质量资格与独立样本；无需因此重跑已完成的功能、标定或庞大矩阵。

训练、teacher、多阶段来源计划、更多模型评分工具、旧模型与重复实验不进入当前任务。额外机制只有在整体收益足以覆盖复杂度时才启用。阶段性交付包含可运行工程、真实正/负结果和明确边界，不等待所有开放研究问题全部解决。
