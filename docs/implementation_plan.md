## 本次完成的关键修正

- 原生 JSON 编码器直接遍历 token 容器，消除写状态/事件时的重复 Python 深遍历；固定 prefill/setup 插值结构在启动时复用。
- 不再把旧回答协议的 580/1024 长度分布套到当前服务；复用原耗时测量，用配置先验、已完成历史和当前服务完成长度估计后续成本。追加/重建的控制成本分别统计，无训练或额外生成。
- 本轮允许 ID 进入 SGLang 原生 regex 解码约束，原生对照同样启用；保留原模型输出，不事后换引用。已有正文与本轮证据完全不相交时重建，有交集则仍比较成本。
- 增加共用的原文来源定位与部分回答规则；真实验证表明它们不能替代语义支持检查，相关失败保留。

## 剩余瓶颈与投入原则

1. **语义适用范围与引用覆盖。** 规范引用资格已由原生约束处理；仍有通用材料被改写为特定对象建议、来源未给出步骤却生成步骤、缺少行内引用的问题。后续只针对来源适用性与回答中的实际论断补齐，不能用范围检查代替语义验收。
2. **相对原生的净收益。** 两个真实检索会话已观测到响应收益，Host 单位占用略高。短回答控制开销、首次检索初始化和生成长度会影响整体结果；不把 CPU 回放、局部命中或本批吞吐当作普遍性能/容量结论。
3. **结果范围。** 当前对照是开发诊断，不是独立冻结测试。正式论文级整体优胜需要明确质量资格与独立样本；无需因此重跑已完成的功能、标定或庞大矩阵。

训练、teacher、多阶段来源计划、更多模型评分工具、旧模型与重复实验不进入当前任务。额外机制只有在整体收益足以覆盖复杂度时才启用。阶段性交付包含可运行工程、真实正/负结果和明确边界，不等待所有开放研究问题全部解决。
